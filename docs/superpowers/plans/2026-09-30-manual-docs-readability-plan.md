## Общие правила для implementer'ов

- Глубина D3: только структура (списки/таблицы/подзаголовки/лиды/акценты/
  лёгкое разбиение предложений/аббревиатуры при первом вхождении). Смысл и

  Заголовки — не переименовывать/не удалять (anchor-ссылки).
- Порядок правок в файле не меняется (кроме выделения лидов в начало

  before/after число «стен» в итоге.

## Методический скрипт (T1 создаёт, переиспользуют T2–T5)

Одноразовый node-скрипт (запускается из корня; НЕ коммитится — постоянный
чек это FU2; команда фиксируется в regression entry):

```
node -e "<скрипт T1>" <файлы...>
```

Логика (методика D4.1):
1. Разбор файла: исключить fenced code blocks (``` … ```).
2. Блоки между `\n\n+`.
3. Для каждого блока:
   - если строки блока — элементы списка (`- `, `* `, `1. `) или таблицы
     (`|`) — мерить ПОСТРОЧНО после очистки префиксов (`- `, `\d+. `, `|`,
     пробелы);
   - иначе (проза) — длина блока (после очистки префиксов строк `#`, `>`,
     пробелов).
4. «Стена» = проза-блок > 600 знаков ИЛИ строка списка/таблицы > 600 знаков.
5. Вывод: `файл:line — N знаков (проза|список|таблица)`; exit 1 при >0.

Baseline (T1 фиксирует числа по 7 файлам до реформата).
