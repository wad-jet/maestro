# Спека: question tool для всех выбор-гейтов (#87, 4.20.0)

Дата: 2026-10-01. Автор: primary (спайк + HITL-решения). Статус: draft.

## Контекст и спайк (I2)

Роадмап #87: «спайк: инвентаризация HITL-вопросов (a)/(b)/(c) в SKILL.md
против нативного question-тула. Если „хватает“ — правки промптов, не мажор.
Ограничение: интерактивный выбор не ослабляет „подтверждение только явным
выбором“ на закрытом перечне гейтов (security-гейты, 1/1.5, D2/D6/D7, плато)».

Данные спайка (2026-10-01):

1. **Гейты:** 15 feature + 3 bugfix (реестр `references/hitl-gate-protocol.md:29–61`);
   ~50 строк (a)/(b)/(c) в `SKILL.md`.
2. **Канон (hitl-gate-protocol.md:9–18, «Правило вопросов (UX)»):** панель —
   только «быстрые формальные выборы» (примеры: гейты 10/17); содержательные
   (a)/(b)/(c) — текстом в сообщении («пользователь может отклонить панель и
   ответить текстом»); свободный текст — обычным вопросом (тул возвращает
   метку, не введённый текст).
3. **Возможности тула (OpenCode `question`):** варианты (label + description),
   recommended = первый вариант + «(Recommended)», авто-опция «ввести свой
   ответ» (custom), multiple (на гейтах не нужен).
4. **Dogfooding (сессия 2026-09-30 → 10-01):** тул использован ~10 раз
   (гейты 10/17 ×4, дизайн-вопросы #85/#97/#103, 13f-HITL) — все отработали,
   **в т.ч. free-form**: на дизайн-вопросе #103 пользователь ответил текстом
   через авто-опцию → панель не лишает возможности отказаться от вариантов.

**Вывод: «хватает»** — тул покрывает все выбор-гейты; содержательные гейты
переносятся на панель без потери (escape hatch — авто-опция). Ограничение
роадмапа соблюдается (D3).

## Дизайн-решения

### D1. Панель — все выбор-гейты (HITL, вариант (a))

Переписать «Правило вопросов (UX)» (глава `hitl-gate-protocol.md:9–18`):

- **Панель (question tool)** — все гейты с **закрытым набором вариантов**:
  - decision: 2, 7, 7b, 10, 12, 17 (когда HITL — manual/auto-answer);
  - контентные: brainstorm Q/A с вариантами, D2/D6/D7, сходимость/плато,
    особый случай 10, 8.6/Точка 2 (security), D5 (бинарные), 13f
    reconciliation, docs-расхождение (14), Tier 3;
  - предпочтения: 0, 1, 1.5.
- **Текст** — чистый свободный ввод: описание фичи, открытые вопросы без
  закрытого набора, свободные имена (имя ветки без вариантов).
- **Fallback:** harness без question tool (Claude Code и др.) — текущее
  поведение: (a)/(b)/(c) текстом в сообщении.

### D2. Формат

- Контекст (правило 1: diff спеки, git log, тесты) — в сообщении **до** панели.
- Варианты (a)/(b)/(c) — options с description.
- Recommended (правило 3а): **первый** вариант + «(Recommended)» +
  «потому что Y» в description (конвенция тула).
- Правило 3 («continue»/«ок» ≠ approval) — без изменений: ответ, введённый в
  авто-опцию, обрабатывается по правилам 3/3а.

### D3. Закрытый перечень — ослабление исключено

- В панели нет варианта «молчание/continue-по-умолчанию» — пользователь
  выбирает вариант **или** вводит явный ответ.
- Явная буква/выбор варианта = approval; «continue»/«ок» — по правилу 3
  (1 шаг, не цепочка).
- Security-гейты (8.6, Точка 2), 1/1.5, D2/D6/D7, плато, особый случай 10 —
  те же правила, подача через панель.

### D4. Edge case — 13f batch

Один гейт 13f с **одним** расхождением — панель; с **несколькими**
(per-сценарий выбор a/b/c не выражается единой панелью) — текст (a)/(b)/(c)
со списком (fallback).
