# Spec: 5.1 — Security: trusted paths вне проекта (L21)

> **Дата:** 2026-10-03
> **Тип:** Architectural security feature
> **Roadmap:** 5.1 → L21
> **Зависимости:** строится после 5.0 (чистая база плагина)

## Цель

Ограничить доступ к персональным/системным путям локальной машины (`~/...`,
`/etc`, `/private`, …) через `custodian` (trusted-модель). Пути относятся к
конфиденциальным: untrusted агенты и primary-сессия получают `deny`; trusted
`custodian` — `allow` с audit-записью.

## Scope

### 1. Классы путей (закрытый список + расширение)

**Default-классы (встроены, не конфигурируются):**

| Класс | Примеры | Примечание |
|---|---|---|
| `user_home` | `~/`, `$HOME/`, `~user/` | Домашние каталоги |
| `etc` | `/etc`, `/etc/ssl`, `/etc/shadow` | Системные конфиги |
| `private_osx` | `/private/var`, `/private/etc`, `/private/tmp` | macOS private |
| `etc_unix` | `/etc/passwd`, `/etc/shadow` (Unix) | Файлы аутентификации |

**Расширяемые классы (через `maestro.json → trusted_paths[].custom`):**
пользователь может добавить свои пути (glob-маски, секция безопасна — только
пути, не содержимое)

### 2. Плагин: guard на tool calls

**Точка входа:** `tool.execute.before` hook в `core.js`

**Логика:**
1. При вызове `read`/`write`/`edit`/`glob`/`grep` проверяем `input.tool` и `output?.args`
2. Резолвим путь через `filePathOf()`
3. Проверяем, попадает ли путь под default-классы или `trusted_paths.custom`
4. Если попадает:
   - **trusted subagent** (`custodian`): `allow` + audit-log запись
   - **untrusted / primary**: `deny` + error `[trusted-path:deny]`
5. Fail-closed: если проверка пути не удалась → `deny`

**Инструменты:** `read`, `write`, `edit`, `glob`, `grep` (bash — через нативные
permissions opencode, plugin guard не нужен)

### 3. Конфигурация `maestro.json`

```json
{
  "trusted_paths": {
    "enabled": true,
    "custom": [
      // Пример: добавить пользовательский путь
      // "~/my-secure-data/**"
    ]
  }
}
```

- `enabled`: `true`/`false` (дефолт `true`, `false` — отключает весь guard)
- `custom`: массив glob-масок (нижний регистр, case-insensitive matching)
- Fail-closed на невалидном конфиге: warn + дефолт `enabled: true`, пустой `custom`

### 4. Security events

- **`trusted_path.access`** (audit-log): `allow` — trusted agent прочитал confidential-путь
- **`trusted_path.deny`** (audit-log): `deny` — untrusted попытался получить доступ
- Формат: `{ sessionID, callID, tool, agent, target: basename, action: "allow"|"deny" }`
- SEC-4b: только агрегаты, без содержимого файлов

## Не входит в 5.1

- Bash-guard для системных путей (nat. permissions opencode покрывают)
- Персональные папки пользователя за пределами `~/` (Future: `~/Documents`, `~/Desktop` и т.п. — добавить в default-классы при первом реальном кейсе)
- Автоматическое обнаружение "чувствительных" путей (только явный конфиг)
