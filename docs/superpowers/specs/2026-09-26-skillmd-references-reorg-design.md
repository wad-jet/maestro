# Spec: Реорганизация SKILL.md → `references/` (главы канона пайплайна)

- Дата: 2026-09-26
- Статус: draft
- Категория: Сложная (ядро изменения — один файл, разложенный на главы; поведение не меняется)
- Версия: 4.13.1 → **4.14.0** (новая фича → minor; правило project-context §3)

## 1. Контекст и проблема

`skills/maestro/SKILL.md` — канон пайплайна, **2400 строк (~100 страниц)**, один файл.
Механика загрузки скилла (tool `skill`) инжектит **весь** SKILL.md в контекст при
каждом старте пайплайна — независимо от того, какой маршрут будет выбран
(feature/bugfix/spike) и какие секции понадобятся.

Последствия:
1. **Стоимость запуска:** ~100 страниц в контексте каждого прогона; половина
   секций (polyrepo, debug-subpipeline, spec-review, model-selection-детали…)
   нужна лишь на конкретных шагах/маршрутах.
2. **Поддерживаемость:** каждая следующая фича (#107 «ревью по типу артефакта»,
   Волна 3: #85/#97/#103) добавляет контент в монолит — файл продолжает расти.
3. **Роадмап:** непокрытый пункт `docs/roadmap.md:111` («Строка 154» — устаревший
   указатель на TODO.md:168 «В SKILL.md остаётся только основа…, детальное
   описание разделов вынести в references/*.md») — решение принято (A6, HITL
   2026-09-26): **разобрать сначала**, отдельной фичей, без изменения поведения;
   #107 — поверх новой структуры.

## 2. Цель

Разложить SKILL.md на **скелет** (всегда нужен) + **главы**
(`skills/maestro/references/*.md`, читаются по требованию на конкретных шагах):

- SKILL.md: 2400 → **~1180 строк** (−50%).
- **Поведение конвейера не меняется**: чистый перенос текста + строки-указатели
  в скелете + шапки глав. Без переписывания, сжатия или изменения смысла.
- Целостность: детерминированный тест ссылок + sweep кросс-ссылок по репо +
  regression entry.

## 4. Механика (решение B2, утверждено HITL)

### 4.1 Строка-указатель в скелете

В точке использования — одна строка в соответствующем шаге/секции:

```
— **<Тема>:** читать `references/<file>.md` из каталога скилла maestro (канон).
```

Правила размещения:
- Указатель — ровно в точке использования (шаг, который тему применяет), не в
  произвольном месте.
- Тема, встречающаяся в N точках — N указателей (дублирование строки допустимо;
  это якоря для оркестратора).
- Если в секции скелета уже есть «см. секцию X» на уходящую тему — ссылка
  заменяется на указатель формата 4.1.

### 4.2 Шапка главы

Каждый файл `references/*.md` начинается шапкой:

```
# <Тема> (глава)

> Канон: <тема>. Грузится из `skills/maestro/SKILL.md` на <точки чтения>.
> Читается оркестратором (имеющим SKILL.md в контексте); внутри главы
> допускаются ссылки «см. SKILL.md, <секция скелета>» и на другие главы.
```

Тело главы — **дословно** из SKILL.md (без переписывания/сжатия). Внутренние
«см. секцию Y SKILL.md» внутри главы: Y остаётся в скелете → ссылка
«см. SKILL.md, <секция>»; Y тоже ушла → относительная ссылка на другую главу.

### 4.3 Доставка

`references/` — подкаталог каталога скилла `skills/maestro/`. Механика доставки
(agpack sync / ручной перенос) копирует каталог скилла **целиком** → изменения
не требуются. `agpack.yml` не меняется (скилл `maestro` уже зарегистрирован,
new-компонент не появляется). `maestro-install/agpack-coverage.test.mjs`
не затрагивается (регистрирует скиллы, не подкаталоги).

### 4.4 Subagent-промпты

`custodian-prompt.md`, `implementer-prompt.md`, `spec-review-prompt.md`,
`stack-detection.md`, `auto-ai-decision-prompt.md`, `invariants.md` — **не
трогаются**: уже self-contained, лежат рядом с SKILL.md.

## 5. Guards целостности (решение B3, утверждено HITL)

### 5.1 Детерминированный тест — `skills/maestro/references-coverage.test.mjs`

Новый тест (Node test runner, без зависимостей), добавляется в `npm test`:

1. **Ссылки разрешаются:** каждое вхождение `references/<имя>.md` в
   SKILL.md → файл существует в `skills/maestro/references/`.
2. **Нет сирот:** каждый файл `skills/maestro/references/*.md` упоминается в
   SKILL.md хотя бы одним указателем.
3. **Шапки на месте:** каждый файл `references/*.md` начинается с заголовка
   `# ` и содержит строку «Канон:».
4. **Скелет не раздулся:** SKILL.md ≤ 1300 строк (защита от регрессии обратно
   в монолит; порог с запасом от целевых ~1180).
5. **Внутренние ссылки глав разрешаются:** ссылки «см. SKILL.md, <секция>» и
   «<другая глава>.md» внутри `references/*.md` → секция/файл существует.

### 5.1b Паритет «чистого переноса» (one-shot проверка, НЕ перманентный тест)

Скрипт (выполняется один раз в SDD, результат фиксируется в regression entry
и отчёте задачи): каждая непустая строка `SKILL.md@<base>` (коммит до
реорганизации) присутствует **дословно** в объединении (новый SKILL.md ∪
`references/*.md`), за исключением явного перечня исключений, зафиксированного
в плане: строки-указатели (4.1), шапки глав (4.2), строки «см. секцию X»,
заменённые указателями (4.1-3), строки с перелинкованными ссылками (4.2).
Заменяет LLM-сверку «дословности» детерминированной проверкой.

### 5.2 Sweep кросс-ссылок (B3b)

По репо — grep на упоминания **перенесённых секций** в связке со SKILL.md
(«секция X», «см. SKILL.md», «канон — SKILL.md, секция…»). Кандидаты (по
скану на 2026-09-26): AGENTS.md, SECURITY.md, commands/*.md (6),
skills/maestro-setup/* (2), skills/maestro-assistant/SKILL.md,
skills/manual-docs/SKILL.md, skills/maestro-feedback-report/SKILL.md,
manual_docs/* (11), docs/project-context.md, agents/sanitizer.md,
skills/maestro/invariants.md, `plugins/maestro-bootstrap/README.md`
(строка 32: «Context Sanitizer (см. SKILL.md)» — живая ссылка на
переносимую секцию).

Правила sweep:
- Упоминание **перенесённой** секции → путь обновляется на `references/<file>.md`.
- Упоминание оставшейся секции (Pipeline, Overview и т.д.) → не трогается.
- Общее упоминание «SKILL.md — канон пайплайна» (без указания секции) → не
  трогается.
- Исторические документы (`specs/**`, `docs/superpowers/**`, `regression/**`,
  changelog-записи про старые версии) → **не трогаются** (снимки).

### 5.3 Regression entry

`regression/entries/2026-09-26-skillmd-references-reorg.md`:
- Сценарий `[Manual]`: старт пайплайна на целевом приложении → оркестратор
  читает главы в точках использования (гейты, диспатчи, security-точки);
  сабагент-промпты загружаются self-contained.
- Сценарий (автоматический): `npm test` → references-coverage зелёный.

1. `npm test` — зелёный (включая новый references-coverage).

   README плагина — одна ссылка по sweep, допустимо).

4. Sweep: 0 оставшихся ссылок на перенесённые секции в «живых» файлах (кроме
   исторических документов — правило 5.2).
5. Ручной дым-прогон (оркестратор/primary): прогнать 2–3 ссылки «на глаз» —
   указатель → файл → шапка → тема на месте (фиксация в regression entry как
   выполнено).
6. `[Manual]`-сценарий 5.3 — фиксируется как ручная проверка (не блокирует
   release). **Первый прогон пайплайна на новой структуре (smoke) —
   обязательное условие** пометки roadmap-пункта как «Выполнено»; до этого —
   «Реализовано, ожидает dogfood».
