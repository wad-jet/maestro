# Спека: режим «простой язык» (plain language) для HITL-обсуждений

Дата: 2026-09-22
Статус: draft
Категория: Сложная фича
Ветка: `feature/plain-language-mode`

**Источник:** TODO п.65 (боль: «приходится писать „Объясни понятным языком"»).
В исходном TODO дефолт был «отключено»; дефолт изменён на `plain` **по решению
пользователя в brainstorm от 2026-09-22** (явная инструкция, supersession).

## 1. Цель и проблема

Пользователю приходится писать «Объясни понятным языком, максимально просто на
примерах», чтобы оркестратор перестал отвечать жаргоном. Нужно включить «простой
язык» по умолчанию (опционально) без повторных просьб.

**Критерий успеха:** при включённом режиме все сообщения пользователю в
top-level primary-сессиях проекта (вопросы, гейты, объяснения, уведомления —
в т.ч. обычные non-maestro чаты; решение brainstorm 2026-09-22: область —
**все primary-сессии проекта**, не только maestro-запуски) — простым понятным
языком: примеры и аналогии вместо жаргона, сложные термины только когда без
них нельзя (с коротким пояснением), техническая конкретика — только по запросу
или когда мысль нельзя донести иначе. Security-находки и точные технические
детали — всегда полностью (escape-clause покрывает: «когда мысль нельзя донести
иначе»).

## 2. Семантика

### 2.1. Ключ `communication` в `maestro.json` (новый верхнеуровневый)

- Значения: `"plain" | "professional"` (enum-строка).
- **Дефолт: `"plain"`** — простой язык включён по умолчанию.
  - Ключ отсутствует → трактуется как `"plain"` (упрощение активно).
  - Явное `"plain"` → то же самое.
- `"professional"` → простой язык выключен (дефолт «не упрощать»).
- Недопустимое значение (не строка / не из enum) → **soft fallback**:
  трактуется как дефолт (`"plain"`) + warn в лог плагина
  (`communication:config_fallback`, только класс ошибки, без значения).
- **Следствие для существующих проектов:** поведение меняется — простой язык
  включается по умолчанию; сохранить старое поведение можно ключом
  `"professional"`.

### 2.2. Флаг `@maestro-init --plain`

- Per-run: явное включение простого языка на этот запуск пайплайна.
- **Приоритет: флаг > конфиг.** При дефолтном `plain` флаг избыточен; его
  смысл — переопределить `"professional"` из конфига на один запуск. Источник
  явно указан в директиве («активирован флагом, переопределяет maestro.json
  professional»).
- Короткой формы нет (только `--plain`).
- Флаг неперсистентный (режим не записывается в `maestro.json`).
- `--plain` — **не режим запуска**: он ортогонален флагам режимов и
  комбинируется (`@maestro-init --auto-answer --plain "…"`); правило парсинга
  снимает оба флага из текста задачи.

### 2.3. Область действия

- **Применяется:** диалог с пользователем в **top-level primary-сессиях
  проекта** (включая non-maestro чаты — осознанное решение: «без повторных
  просьб» должно работать везде) — вопросы, HITL-гейты, объяснения,
  уведомления в чате (в т.ч. авто-уведомления авторежимов).
- **НЕ применяется:** артефакты (спецы/планы/код/доки — остаются техническими),
  **субагенты** (task-сессии — инъекция в них запрещена, реализовано
  parentID-фильтром, §3.2), промпты диспатча.

## 3. Механика (плагин `maestro-bootstrap`)

Конфиг-активация — **исключительная зона ответственности плагина**: primary
нельзя читать `maestro.json` (нативный deny), поэтому скилл/команда сами
конфиг проверить не могут. Разделение ролей: **поведение корректирует только
плагин** (по конфигу, через инъекцию директивы) **и сам оркестратор** (по
флагу `--plain`, распознанному в тексте команды); скилл — носитель правил,
не читатель конфига. Падение без плагина: в проекте **без** `maestro.json`
(гейт 0 пропускается) флаг `--plain` работает (команда инструктирует
оркестратора напрямую); в проекте **с** `maestro.json` без плагина гейт 0
жёстко останавливает пайплайн — и флаг, и конфиг неактивны (degraded-mode не
существует).

### 3.1. Разбор конфига

- `loadCommunicationConfig(config)` в `core.js` (рядом с другими лоадерами):
  возвращает `{ mode: "plain" | "professional", explicit: boolean,
  invalid: boolean }`.
  - ключ отсутствует → `{ mode: "plain", explicit: false, invalid: false }`;
  - валидное значение → `explicit: true`;
  - невалидное → `{ mode: "plain", explicit: false, invalid: true }`.

### 3.2. Хуки

- `chat.message` (только top-level primary-сессии, паттерн memory-модуля):
  текст сообщения содержит команду `@maestro-init`/`/maestro-init` **и** флаг
  `--plain` (целое слово) → сессия помечается «plain по флагу» в bounded-мапе
  (паттерн `makeBoundedMap`), log `communication:flag_plain` (sessionID, без
  текста сообщения).
- `experimental.chat.system.transform`: если `mode === "plain"` (конфиг или
  дефолт) ИЛИ сессия помечена флагом → в `out.system` пушится **короткая
  самодостаточная директива** (текст — §4), с указанием источника:
  Матрица source-лейблов (полная):
  - конфиг явный `"plain"` → «источник: maestro.json (communication: plain)»;
  - ключ отсутствует ИЛИ invalid-fallback → «источник: дефолт (plain)»;
  - флаг + config `plain` → «источник: флаг --plain» (без слова
    «переопределяет» — переопределения нет);
  - флаг + config `professional` → «источник: флаг --plain (переопределяет
    maestro.json professional)».
  - **Guard:** директива инжектится только для top-level primary-сессий:
    (1) `client.session.get` → `parentID` пуст (lookup с кэшированием, общий с
    memory-модулем на уровне плана, чтобы не дублировать `session.get` на
    каждое сообщение) — исключены task-сессии субагентов (требование §2.3);
    (2) **исключены сервис-сессии плагина** (title-префикс `[maestro-memory]`,
    паттерн `SESSIONS` memory-модуля) — саммаризатор и git-backfill создают
    top-level сессии без parent; инъекция в них деградирует quality
    `title/summary/decisions` записей памяти.
- **Инвариант:** `experimental.chat.messages.transform` остаётся `undefined`.
- **Coexistence:** хуки communication сливаются с хуками memory тем же
  chain-паттерном, что и существующий memory-wiring в `MaestroBootstrapPlugin`
  (оба модуля могут регистрировать `chat.message` / `system.transform`).
- **Fail-soft:** любая ошибка communication-логики → catch + log, остальные хуки
  не затрагиваются (глобальный инвариант плагина).
- Лог-события: `communication:config_fallback` (warn), `communication:flag_plain`
  (info), `communication:directive_injected` (debug; только sessionID +
  источник, без текста).

### 3.3. Флаг-детекция

- Регулярное определение флага — отдельная чистая функция
  `detectPlainFlag(text) → boolean` (тестируема изолированно).
- Детекция по первому сообщению сессии, содержащему команду; повторные
  появления флага в последующих сообщениях той же сессии не требуют
  повторной инъекции (маркировка сессии — idempotent).
- **Known limitation (принятый прецедент, как у `--auto-answer`):** текст
  задачи, содержащий подстроку команды + `--plain` (напр., мета-задача про
  саму фичу), даст ложную маркировку — принимается как допустимый риск.

## 4. Текст директивы (инъекция)

Короткая самодостаточная директива на русском (точная формулировка — в коде
плагина; смысл согласован с пользователем):

> Общайся с пользователем простым понятным языком: примеры и аналогии вместо
> жаргона; сложные термины — только когда без них нельзя, с коротким
> пояснением; техническая конкретика — только по запросу или когда мысль не
> донести иначе. Не распространяется на артефакты (спецы/планы/код/доки) и на
> субагентов. Security-находки и точные технические детали — всегда
> полностью. Источник: <maestro.json (communication: plain) | дефолт (plain)
> | флаг --plain | флаг --plain (переопределяет maestro.json professional)>.

## 5. Канон в скилле и команде

- **`skills/maestro/SKILL.md`** — новая секция «Простой язык (plain language)»:
  полная формулировка правил (см. §2.3), условие активности (директива плагина
  в системе ИЛИ флаг `--plain` распознан при парсинге команды), объявление
  активации в чате на старте пайплайна (с источником).
- **`commands/maestro-init.md`** — строка `--plain` в таблице флагов режима;
  правило парсинга (флаг убирается из текста задачи, передаётся в pipeline);
  объявление активации.
- **`skills/maestro-assistant/SKILL.md`** — новый ключ `communication`
  (единственный источник правил конфига) + **способность менять режим**:
  процедура смены `plain` ↔ `professional`: чтение через bash (нативный
  read-deny), правка через `edit` (нативный ask → HITL-подтверждение),
  объяснение последствий (дефолт, приоритет флага, область действия) и
  **обязательное сообщение о перезапуске opencode** (OP-1: конфиг плагина
  читается один раз при init — без рестарта эффект не наступит).
- **`skills/maestro-setup/SKILL.md`** — при подготовке `maestro.json`
  **HITL-вопрос выбора режима**: «Какой режим коммуникации? (a) plain —
  простой язык по умолчанию (рекомендуется) — (b) professional»; выбор
  записывается в ключ `communication`.

## 6. Документация (`manual_docs/`, Diátaxis)

- `reference/config.md` — ключ `communication` (значения, **дефолт `plain`**,
  fallback).
- `reference/commands.md` — синтаксис/флаг `--plain` в `@maestro-init`
  (каноническое место флагов команды).
- `how-to/` (настройка проекта — maestro-setup / maestro-assistant) —

- `explanation/` (как плагин активизирует режим) — механика §3.
- `overview/changelog.md` — запись `[Unreleased]` (указать изменение

  существующих проектов; откат — `"professional"`).

## 7. Тесты

Unit-тесты (Node test runner, файл `plugins/maestro-bootstrap/index.test.js`
— тот же placement, что и регрессионный прогон):

1. `loadCommunicationConfig`: отсутствует → `{plain, explicit:false}` /
   `"plain"` / `"professional"` (explicit) / невалидное (число, строка вне
   enum) — soft fallback в `plain` + `invalid: true`.
2. `detectPlainFlag`: флаг есть/нет, целое слово (не `--plainly`), команда
   `@maestro-init` vs `/maestro-init`, флаг без команды (не считается).
3. `chat.message` → маркировка сессии: флаг + команда → помечена; без команды →
   нет; субагентская сессия (parentID) → игнор.
4. `system.transform`: config `plain` (explicit) → директива с лейблом
   maestro.json; config отсутствует (дефолт) → директива с лейблом «дефолт»;
   config `professional` → нет; флаг в сессии + config `professional` →
   директива с    пометкой переопределения; флаг в сессии + config `plain` (включая
   дефолтный, ключ отсутствует) → директива с лейблом «флаг --plain» (без
   «переопределяет»); **task-сессия (parentID задан) → директива НЕ
   инжектится ни по какой ветке**; **сервис-сессия (title
   `[maestro-memory]…`, parentID пуст) → директива НЕ инжектится**;
   invalid-fallback → директива с лейблом «дефолт»; текст директивы всегда
   содержит источник.
5. Coexistence: memory-хуки и communication-хуки одновременно работают
   (оба `chat.message`/`system.transform` не затирают друг друга).
6. Инвариант: `experimental.chat.messages.transform` === undefined.
7. Fail-soft: ошибка в communication-ветке не ломает остальные хуки.

Регрессия: полный прогон `node --test plugins/maestro-bootstrap/index.test.js`
зелёный.

Regression registry: entry в `regression/entries/` (изменение hook-wiring
плагина + риск коэксистенции с memory-хуками + флип дефолта для существующих
проектов + риск инъекции в сервис-сессии `[maestro-memory]` — guard по
parentID + title-префиксу).

## 9. Out of scope

- «Professional»-флаг для временного отключения на запуск (YAGNI; дефолт конфига
  уже покрывает).
- Настройка стиля/тона beyond plain (напр., уровень детализации).
- Влияние на субагентов, артефакты, язык спеков.
- Локалилизация директивы (русская только — рабочий язык проекта).
