# Спека: самопроверка устаревания maestro-update.sh

- **Дата:** 2026-09-04
- **Ветка:** `feature/update-self-version-check`
- **Категория:** Сложная фича (полный pipeline)
- **Источник:** задача пользователя: «Скрипт maestro-update.sh при запуске должен
  проверять собственную версию на устаревание. Если есть более новая версия
  скрипта — предложить обновить или самообновиться».

## 1. Проблема

`maestro-update.sh` скачивается в целевой проект один раз при первичной установке
(`maestro-install.sh`, шаг 6). Логика обновления живёт **в самом скрипте**:
merge-add канонических записей `agpack.yml`, rename-aware миграции, очистка
stale-артефактов, очистка кэша плагина. При релизе с изменённой логикой проект
со старым скриптом применяет **новый** канон `maestro-install/agpack.yml`
**старой** логикой — расхождение поведения, которое невидимо для пользователя.
Прецедент: rename-миграция v2.0.0 (`skills/maestro-init` → `skills/maestro-new`)
существовала только в скрипте — проект, не перескачивавший его, не получал
исправление.

## 2. Зафиксированные решения (сессия 2026-09-04, brainstorm HITL)

| # | Решение |
|---|---|
| 1 | Детекция — **сравнение содержимого** (content-diff): скрипт целевого источника vs локальный файл `${BASH_SOURCE[0]}`. Версионные константы и штампы в `.maestro/` отклонены (дрейф / эфемерность) |
| 2 | Точка проверки — **после шага 2** (`$TMP_DIR` с целевым источником уже создан, read-only) и **до шага 3** (первая мутация). Без доп. сетевых вызовов — переиспользуется fetch шага 2 |
| 3 | При `--pin <sha>` сравнение идёт с `maestro-update.sh` **закреплённого коммита** — семантически: «локальный скрипт соответствует целевой версии» |
| 4 | Гейт при расхождении: `(a) самообновить и перезапустить (рекомендую) / (b) продолжить текущим / (c) стоп`. Самообновление = атомарная перезапись локального файла + `exec` перезапуск с теми же аргументами. Терминация цикла **механическая**: `exec` передаёт env-маркер `MAESTRO_UPDATE_SELF_UPDATED=1`, при котором self-check во втором круге пропускается (`info`) — не по аргументу «расхождение исчезнет», а by construction (main может двинуться между fetch первого и второго круга) |
| 5 | stdin не tty → `die` с инструкцией обновить скрипт вручную (fail-safe, без молчаливых мутаций); новые флаги (`--yes` и пр.) не добавляются (YAGNI) |
| 6 | «Отличается» **не различает** направления (старше/новее) — сообщение формулирует расхождение, не «устаревание»; локальные правки пользователя и более новый скрипт обрабатываются одинаково (гейт, вариант (b) оставляет выбор) |
| 7 | Scope: только `maestro-update.sh`. `maestro-install.sh` не затрагивается (одноразовый, скачивается свежим при каждом запуске через curl по инструкции) |

## 3. Архитектура изменений

### 3.1. `maestro-update.sh`

**Новое в начале (до парсинга флагов, после констант):**

```bash
SCRIPT_PATH="${BASH_SOURCE[0]}"
ORIG_ARGS=("$@")   # сохранить до парсинга — для re-exec после самообновления
```

**Новый шаг 2a (после шага 2, до шага 3):**

0. **Guard терминации:** если в окружении `MAESTRO_UPDATE_SELF_UPDATED=1`
   (re-exec после самообновления) → `info "самопроверка пропущена (скрипт
   только что самообновлён)"` и пропуск всего шага 2a — терминация цикла by
   construction, не зависит от движения main между fetch.
 1. Извлечь целевой скрипт — **единый способ на обоих путях: `git show` (raw
   blob, без smudge-фильтров)**; `core.autocrlf` (Git Bash: `true` по умолчанию)
   не влияет на сравнение, и (a) пишет LF-содержимое (stdout-редирект;
   stderr глушится `2>/dev/null`, чтобы ожидаемый сбой не шумел):
   - `--pin`: `git -C "$TMP_DIR" show "$PIN:maestro-update.sh" > "$TMP_DIR/update-target.sh" 2>/dev/null`
   - default: `git -C "$TMP_DIR" show "HEAD:maestro-update.sh" > "$TMP_DIR/update-target.sh" 2>/dev/null`

   Код возврата `git show` обрабатывается **в `if` ПОСЛЕ вызова** (не `|| true`
   при уже выполненном редиректе — редирект `>` создаёт/truncate-ит файл до
   запуска команды, и «пустой файл» был бы неотличим от «файла нет»):
   - успех → файл готов к сравнению;
   - сбой (файла нет в коммите) → `rm -f "$TMP_DIR/update-target.sh"`,
     `info "maestro-update.sh отсутствует в целевой версии — самопроверка
     пропущена"`, гейт пропускается.
 2. **Если `$TMP_DIR/update-target.sh` существует и непуст** (`[ -s ]`; иначе →
    `info`, гейт пропускается): сравнение вызывается **в `if`** (set -e):
    `if cmp -s "$SCRIPT_PATH" "$TMP_DIR/update-target.sh"; then` → идентично:
    `info "maestro-update.sh актуален"` и продолжение; расхождение (exit 1) →
    гейт. Exit 2 `cmp` (нечитаемый файл) — **не расхождение**: `warn "нечитаемый
    файл для сравнения — самопроверка пропущена"`, гейт пропускается,
    продолжение.
 3. **Гейт** (только при расхождении):

 ```
 [maestro-update] maestro-update.sh отличается от целевой версии ($TARGET_VERSION).
   (a) Самообновить скрипт и перезапустить (рекомендую)
   (b) Продолжить текущим скриптом
   (c) Стоп
 ```

    - stdin не tty (`[ -t 0 ]` false) → `die "самобновление недоступно в
      неинтерактивном режиме; обновите вручную: $REPO_URL (maestro-update.sh) и
      повторите"`.
    - **Семантика ввода** (цикл `read -r`): `a` → (a); `b` → (b); `c` → (c);
      пустой Enter или любая другая строка → `info "введите a, b или c"` и
      повторный запрос; EOF (Ctrl-D, `read` вернёт non-zero) → `die "ответ не
      получен — остановлено"`. Молчаливое (a) по умолчанию запрещено
      (решение 5: самомутация — только явным выбором).
    - **(a)**: записать `$TMP_DIR/update-target.sh` → temp-файл рядом с
      `$SCRIPT_PATH` + `mv` (атомарно, частичного файла нет); затем
      `rm -rf "$TMP_DIR"` (явно — `exec` заменяет процесс, EXIT-trap
      `rm -rf "$TMP_DIR"` не сработал бы; новый процесс создаст свой TMP_DIR)
      и `exec env MAESTRO_UPDATE_SELF_UPDATED=1 bash "$SCRIPT_PATH"
      ${ORIG_ARGS[@]+"${ORIG_ARGS[@]}"}` (env-маркер — guard терминации п.0;
      безопасное раскрытие пустого массива в bash 3.2 под `set -u`).
      Запуск по symlink: `mv` заменит symlink, а не его цель (документировать в
      §3.2; безвредно — целевая копия останется, но stale).
    - **(b)**: `warn "продолжаю текущим maestro-update.sh (расхождение не
      устранено)"` → продолжение.
    - **(c)**: `warn "останавливаюсь (выбор пользователя)"` → `exit 1`.
    - Сбой записи (file not writable и пр.) на (a) → `die` **до** `exec`
      (локальный файл не тронут).

**Ничего не меняется** в шагах 1, 3, 3a, 4 и далее: merge-add, agpack sync,
очистки, версионный отчёт — как есть.

### 3.4. `regression/entries/2026-09-04-update-self-version-check.md` (новый)

Формат — как у существующих entries: frontmatter (`version: 1`, `feature:`,
`added:`, `status: active`, `risk: MEDIUM` — меняется поведение запуска
обновление-скрипта, есть self-modification), `## Суть`, per-сценарные
`path`/`run`/`workdir`/Ожидание (референс: `2026-09-04-install-agpack-canon.md`).

Сценарии (scratch-каталог вне репо, фиктивный целевой проект с `agpack.yml`
и `package.json`):

1. **Синтаксис:** `bash -n maestro-update.sh` — exit 0.
2. **Расхождение + самообновление (pre-merge).** Запускать **копию** нового
   скрипта в scratch, НЕ файл из working tree репо — (a) перезаписывает
   `$SCRIPT_PATH` и затрёт непоммиченные правки. До мержа `main` содержит
   СТАРЫЙ скрипт (без self-check) → default-путь проверяет downgrade-сценарий:
   локальный (новый, намеренно/фактически отличающийся) скрипт → гейт;
   (a) → файл перезаписан целевым (старым) содержимым, re-exec, обновление
   продолжается (гейт повторно невозможен — старому скрипту его нет).
   Ожидание: no partial file, exit 0, agpack sync выполнен.
3. **Identity-путь (только когда цель содержит новый скрипт).**
   `--pin <sha фиче-коммита, pushed в origin>` + локальный скрипт == скрипт
   пина → гейта нет, `info "maestro-update.sh актуален"`, обновление
   продолжается. Обязательный повторный прогон **post-merge** (main содержит
   новый скрипт): идентичный → «актуален»; отличающийся → гейт; (a) → re-exec
   → guard `MAESTRO_UPDATE_SELF_UPDATED=1` → гейт второй раз НЕ показывается,
   обновление продолжается.
4. **`--pin <sha>` (расхождение):** pin на коммит, чей скрипт отличается от
   локального → гейт с версией пина; (b) → `warn` + продолжение текущим;
   (c) → `warn` + exit 1. Отдельно (guard pre-merge): pin на фиче-sha +
   намеренно расходящаяся локальная копия → (a) → re-exec нового скрипта →
   `info "самопроверка пропущена (скрипт только что самообновлён)"` →
   обновление продолжается (детерминированная проверка инварианта I3 до
   мержа). Пин-коммит **без** `maestro-update.sh` (до
   2026-08-30) → `info`, гейт пропускается, локальный файл НЕ тронут
   (верификация C1: пустого файла не остаётся, (a) не затирает скрипт).
5. **Non-tty при расхождении** (`< /dev/null`) → `die` с инструкцией; файл не
   тронут.
6. **EOF/пустой ввод в гейте** (запуск в реальном tty — интерактивно или
   `script -q /dev/null bash …`; pipe-stdin не подходит — даст non-tty `die`
   из сценария 5): пустой Enter → повторный запрос; Ctrl-D →
   `die "ответ не получен — остановлено"`, файл не тронут.
7. **Тесты плагина:** `node --test plugins/maestro-bootstrap/index.test.js` —
   173/173 pass (плагин не затронут, sanity).

## 4. Обработка ошибок — сводка

| Случай | Поведение |
|---|---|
| `MAESTRO_UPDATE_SELF_UPDATED=1` в окружении | self-check пропущен (`info`), продолжение — guard терминации re-exec |
| Сбой clone/fetch (шаг 2) | существующий `die` (без изменений) |
| `git show` не нашёл `maestro-update.sh` (пин/HEAD) | `rm -f` целевого temp-файла, `info`, гейт пропускается (деградация, не ошибка) |
| `cmp` exit 2 (нечитаемый файл) | `warn`, гейт пропускается — не трактуется как расхождение |
| Расхождение + non-tty | `die` с URL для ручного обновления |
| Расхождение + невалидный ввод (пусто/мусор) | `info` + повторный запрос; молчаливого (a) нет |
| Расхождение + EOF в гейте | `die "ответ не получен — остановлено"` |
| Расхождение + (a) + сбой записи | `die` до `exec`, локальный файл не тронут |
| Расхождение + (a) успех | temp+`mv`, `rm -rf "$TMP_DIR"`, `exec env MAESTRO_UPDATE_SELF_UPDATED=1 bash …` |
| Расхождение + (b) | `warn`, продолжение текущим скриптом |
| Расхождение + (c) | `warn`, `exit 1` |
| Пустой `ORIG_ARGS` под `set -u` (bash 3.2) | `${ORIG_ARGS[@]+"${ORIG_ARGS[@]}"}` — без unbound-variable |

## 6. Ограничения и осознанные трейд-оффы

1. **Направление расхождения не различается** (решение 6): локально
   модифицированный или более новый скрипт дают тот же гейт. Формулировка
   «отличается» честна; (b) сохраняет выбор пользователем.
2. **Самообновление при `--pin` берёт скрипт из пин-коммита**, а не из main —
   согласовано с семантикой пина (вся цель обновления — целевая версия).
3. **Нет флага авто-самообновления** (`--yes`) — YAGNI; неинтерактивный режим
   получает fail-safe `die`, не авто-мутацию.
