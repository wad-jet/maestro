# План: проверка наличия скилов superpowers в `/maestro-init`

> Статус: **зафиксирован, реализация НЕ начата**.
> Дата: 2026-08-19. Репо: `maestro-agent` (authoring).
> Решения: runtime-пробник через `skill` tool; ядро SDD (3 скила); установка через HITL
> (оркестратор выполняет команду сам); при отказе — продолжить с предупреждением.

## Постановка

`/maestro-init` (скилл `init`, `skills/init/SKILL.md`) должен проверять наличие
установленных скилов superpowers (`https://github.com/obra/superpowers`, папка
`skills`). Если скилы не установлены — предложить установку через HITL.

**Зачем:** pipeline maestro жёстко зависит от superpowers-скилов (REQUIRED
SUB-SKILLS в `skills/maestro/SKILL.md`: `writing-plans`,
`subagent-driven-development`, `test-driven-development` и др.). Если их нет —
SDD-шаги (план, исполнение, TDD) работать не будут. Проверка на этапе init
предотвращает «мёртвую» инициализацию.

## Как определяется «установлено»

**Runtime-пробник через `skill` tool** (не проверка конфигов):

- Оркестратор вызывает `skill` tool для **трёх ядерных скилов SDD**:
  - `writing-plans`
  - `subagent-driven-development`
  - `test-driven-development`
- Если любой вернул ошибку `Skill "<name>" not found` → скилы superpowers
  **не установлены** (или установлены частично — фиксируем список недостающих).
- Все три найдены → superpowers **установлен**, продолжаем init.

Почему пробник, а не `opencode.json`: `skill` tool сигналит об отсутствии
надёжно (`not found` + список доступных); детектит **фактическую** доступность,
независимо от способа установки (плагин, ручное копирование, зеркало
`.opencode/`). Проверка конфигов обманывает в обе стороны (запись есть, пакет
сломан; скилы скопированы без записи).

## Flow (новый pre-flight шаг в `skills/init/SKILL.md`)

Расположение: блок «Предусловия (pre-flight)», после «3. Git-состояние»
(независимо от контекста проекта).

1. **Пробник:** загрузить три скила через `skill` tool.
2. **Все найдены** → пометить `superpowers: ok`, перейти к следующему шагу.
3. **Недостающие найдены** → HITL:

   Показать пользователю:
   - список недостающих скилов;
   - команду установки;
   - вопрос: «(a) установить глобально (`-g`) — (b) установить в проект — (c) пропустить».

   Рекомендация — (a) глобально: скил доступен во всех проектах.

4. **Выбор (a)/(b):** оркестратор выполняет команду сам через `bash`
   (команда показывается и подтверждается HITL):

   ```
   opencode plugin -g superpowers@git+https://github.com/obra/superpowers.git   # (a)
   opencode plugin superpowers@git+https://github.com/obra/superpowers.git       # (b)
   ```

   После выполнения — **повторный пробник** для подтверждения.
   Установлено → `superpowers: ok`.

5. **Выбор (c) (пропустить):** init **продолжается**, в `.maestro/last-run.md`
   и финальном своде — явная пометка: «superpowers НЕ установлен — SDD-шаги
   pipeline maestro (план, исполнение, TDD, ревью) работать не будут»
   (fail-open с предупреждением, без блокировки init).

## Поведение при сбое

| Ситуация | Действие |
|---|---|
| Команда установки упала (сеть, git) | HITL: повторить / показать команду пользователю для ручного запуска / пропустить |
| Пробник после установки всё ещё не находит | HITL: повторить установку / пропустить с предупреждением |
| Отказ (c) | Продолжить, пометка в last-run.md + своде |

## Известные ограничения

- Пробник загружает содержимое скилов в контекст (разово при init) — приемлемо.
- Проверяются только 3 ядерных скила SDD; вспомогательные
  (`using-git-worktrees`, `requesting-code-review`, `finishing-a-development-branch`,
  `systematic-debugging`) не пробуются — они производные от того же пакета
  superpowers, частичная установка невозможна без ядра.
- Ограничение HITL-gate: «Запустить pre-flight диагностику?» (.TODO.md п.6) —
  вне скоупа этого плана.
