# @maestro-init

Загрузи skill `maestro` (tool: skill) и следуй pipeline из SKILL.md.
Координируй субагентов (custodian, haiku, sonnet, opus, fable, reviewer, sanitizer)
на каждом этапе.

Работает в любой primary-сессии — привязки к конкретному агенту нет.

## Режимы запуска

`@maestro-init [<флаг-режима>] [--plain] [<задача>]` — режим задаётся флагом. Задача — необязательный параметр:
- **Без задачи:** оркестратор загружает пайплайн, затем предлагает сформулированную из контекста текущей сессии задачу (HITL с возможностью редактирования). Если контекста нет — обсуждение задачи начинается с нуля.
- **С задачей:** задача передаётся в пайплайн как ранее (обратная совместимость).

| Флаг | Режим | Описание |
|---|---|---|
| *(без флага)* | manual | Текущее поведение: полный HITL-контроль, все гейты подтверждаются вручную |
| `--auto-answer` / `-aa` | auto-answer | Полный флоу: все шаги/проверки/ревью выполняются, но рекомендации на рутинных гейтах принимаются автоматически (с уведомлением в чат). Гейты 10 (spec), 17 (merge), security-гейты, контентные вопросы, чувствительные изменения (⚑4) — всегда вручную |
| `--auto-ai` / `-ai` | auto-ai | Максимальная автономность: ИИ сам принимает решения (маршрут, project-context, контентные вопросы — с доп. анализом через decision-диспатч sonnet/opus), механика — ralph loop. Гейты 10/17 и чувствительные изменения — всегда вручную. Security — гибрид (только risk-reducing дефолты) |
| `--no-auto` | manual (явно) | Явное отключение авторежима, полный ручной контроль |

Синтаксис: `@maestro-init --auto-answer` · `@maestro-init` · `@maestro-init --plain` ·
`@maestro-init --auto-answer "Реализуй экспорт CSV"` (обратная совместимость).

Правило парсинга: распознать флаг режима и `--plain` (если есть), убрать их из текста.
Если после флагов остался текст — он интерпретируется как задача (обратная совместимость).
Если текста нет — задача генерируется из контекста текущей сессии (см. ниже). Режим —
per-run, не персистится в `maestro.json`.

## Генерация задачи из контекста сессии

Если `@maestro-init` вызван без текстовой задачи:

1. Оркестратор анализирует последние сообщения текущей primary-сессии — ищет
   обсуждение проблемы, гипотез, решений, артефакты (код, логи, дифы).
2. Формулирует задачу на основе найденного контекста.
3. Показывает сформулированную задачу пользователю:
   > **Предлагаемая задача:** <формулировка>
   >
   > (a) Так / (b) Переформулировать — (c) Отмена
4. При (b) — обсуждение задачи в чате (стандартный brainstorming-путь).

Это позволяет не формулировать задачу вручную, если она уже обсуждалась
в текущей сессии (например, в Plan mode перед вызовом `@maestro-init`).

**Важно:** автогенерация — помощь, не замена обсуждения. Пользователь всегда
может предложить свою формулировку или ответить (b) для полноценного обсуждения.

## Флаг `--plain` (простой язык)

`--plain` — НЕ режим запуска: ортогонален флагам режимов и комбинируется
(`@maestro-init --auto-answer --plain`). Per-run, не персистится.
Включает простой язык на этот запуск; **флаг > конфиг** `maestro.json`
(даже при `communication: "professional"`).

| Синтаксис | Эффект |
|---|---|
| `@maestro-init --plain` | простой язык на этот запуск (без задачи) |
| `@maestro-init --plain "задача"` | простой язык на этот запуск (с задачей) |

Правило парсинга: снять `--plain` из текста задачи (вместе с режим-флагом —
оба), передать в pipeline. Канон правил — `skills/maestro/SKILL.md`, секция
«Простой язык (plain language)»; активация по конфигу — плагин (инъекция
директивы, до загрузки скилла).

## Ключевые правила

- Следуй HITL gates строго
- Все HITL gates, вопросы и сообщения пользователю — ТОЛЬКО на русском языке
- Режим запуска задаётся флагом (см. выше) и передаётся в pipeline как per-run параметр
- После утверждения плана (шаг 12) — один коммит `docs: design + plan for <feature-name>`
- После SDD (шаг 13) — per-task code коммиты
- Финальное ревью (шаг 16) — диспатч reviewer
- В Plan mode (ресеч, обсуждение фичи/багфикса, подготовка spec) и на ресече
  bugfix — сначала `memory_search` по теме задачи (канон: `skills/maestro/references/memory-layer.md`); память не включена → молча пропуск

## Связанные команды

- `@regression` — реестр рисков регрессии
- `@maestro-setup` — инициализация maestro для нового или уже существующего проекта
