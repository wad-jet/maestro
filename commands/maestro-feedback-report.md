# @maestro-feedback-report

Собери фактуру по прошлым процессам с участием maestro **в текущей сессии** для
последующей ретроспективы (проведение ретроспективы здесь НЕ требуется — только
сбор). Пользователю предлагается оставить комментарии/рекомендации к отчёту —
они записываются в секцию `## Пользовательский фидбек` итогового файла.

**Язык:** все HITL-вопросы, варианты и сообщения пользователю — только на русском.

## Шаг 1. Вызвать скилл

Выполни: `skill maestro-feedback-report`

Скилл соберёт фактуру и сохранит отчёт в `.maestro/feedback-reports/report-<Session ID>-<YYYY-MM-DD>.md`.

## Шаг 2. HITL: запрос фидбека от пользователя

1. Покажи краткую выжимку из отчёта:
   - Session ID, дата
   - Список фич/задач
   - Ключевые находки (что хорошо / что плохо / проблемы)
2. Укажи секцию безопасности из отчёта:
   - `sanitizer.redacted: <кол-во>`, `confidential.access: <allow/deny>`,
     `access_policy.blocked: <кол-во>`
   - Если все нули: "Событий безопасности не выявлено."
3. Запроси:
   "Нужно ли что-то исправить в фактуре отчёта?
   - Да: опиши что исправить → скилл перезапустится для обновления
   - Нет: введи рекомендации/комментарии к отчёту (Enter — пропустить)"
4. Если **правка фактуры** → записать ввод пользователя в `## Пользовательский фидбек`
   в текущий отчёт (для сохранения), затем выполнить `skill maestro-feedback-report`
   для перегенерации. После завершения скилла — восстановить извлечённый блок
   `## Пользовательский фидбек` в новый отчёт (в самый конец, после всех секций,
   включая «Безопасность»).
   Сообщи: "Отчёт обновлён. Фактура исправлена, комментарии сохранены."
5. Если **рекомендации** (без правок фактуры) → записать секцию `## Пользовательский
   фидбек` в самый конец отчёта (после всех секций, включая «Безопасность»).
   Сообщи: "Отчёт сохранён в `<путь>`. Комментарии ✓."
6. Если нажат Enter (без текста) → секцию НЕ создавать. Сообщи: "Отчёт сохранён
   в `<путь>`. Комментарии пропущены."
