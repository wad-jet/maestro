# @maestro-feedback-report

Собери фактуру по прошлым процессам с участием maestro **в текущей сессии** для
последующей ретроспективы (проведение ретроспективы здесь НЕ требуется — только
сбор). Отчёт сохраняется в `.maestro/feedback-reports/report-<Session ID>-<YYYY-MM-DD>.md`.

**Язык:** все HITL-вопросы, варианты и сообщения пользователю — только на русском.

## Шаг 1. Определить текущую сессию

1. Получи `Session ID` текущей сессии через `opencode session list` (текущая —
   самая последняя по времени создания/обновления, либо подтверди у пользователя).
2. Определи текущую дату `YYYY-MM-DD` (формат ISO).
3. Вычисли путь отчёта:
   `.maestro/feedback-reports/report-<Session ID>-<YYYY-MM-DD>.md`.

## Шаг 2. Собрать фактуру из диалога текущей сессии (основной источник)

Проанализируй ход текущей сессии и зафиксируй качественную фактуру:

- Какие фичи/задачи обрабатывались через maestro (или его команды:
  `@maestro`, `@maestro-init`, `@maestro-design`).
- HITL-гейты: какие пройдены, где буксовали, где были отмены/повторы.
- Ключевые решения, шаги, отклонения от плана.
- Стопоры и проблемы, замеченные по ходу.

## Шаг 3. Дополнить данными из логов плагина (автоматически, если есть)

Проверь `.maestro/maestro-bootstrap-*.log` (JSONL) на наличие записей с полем
`sessionID`, равным текущей сессии. Если записи есть — агрегируй:

- **task-диспатчи** (`tool.execute.before`/`after`): количество, средняя/макс
  длительность (`durationMs`), тайтлы.
- **`session.error`** — ошибки сессии.
- **`session.status.retry`** — повторы (attempt, message — напр. rate limit).
- **`tool.execute.after.empty_result`** — пустые результаты сабагентов.
- **`sanitizer.redacted`** — что замаскировано (без содержимого).
- **`access_policy.blocked`** — блокировки доступа.

Если записей по `sessionID` нет — в отчёте пометь секцию «нет данных по логам
плагина».

## Шаг 4. Собрать отчёт

Создай каталог `.maestro/feedback-reports/` (если нет) и запиши файл по пути из
Шага 1 со структурой:

```markdown
# Feedback Report — <Session ID> — <дата>

## Метаданные
- Session ID: <id>
- Дата: <YYYY-MM-DD>
- Фичи/задачи: <список>
- Команды maestro: <@maestro, @maestro-init, @maestro-design ...>

## Ход процесса
<chronology: шаги, гейты, решения>

## Что было хорошо
<qualitative>

## Что было плохо
<qualitative>

## Проблемы, с которыми столкнулись
### Из диалога
<стопоры, HITL-буксования, отклонения>

### Из логов плагина
<или «нет данных по логам плагина»>
- task-диспатчи: <кол-во, длительности>
- session.error: <...>
- retry: <...>
- empty_result: <...>
- sanitizer.redacted: <...>
- access_policy.blocked: <...>

## Критические замечания / рекомендации
<кратко, только если есть выраженные критические моменты>
```

## Завершение

- Сообщи: «Отчёт сохранён в `<путь>`».
- HITL: «(a) посмотреть/дополнить отчёт — (b) ок».
- **Автокоммит НЕ требуется** — коммит отчёта на усмотрение пользователя
  (`.maestro/` обычно эфемерное/в gitignore).
