# SECURITY — Требования и оценка информационной безопасности (ИБ)

> Статус: **актуально**. Дата: 2026-08-24. Версия: 1.
> Репо: `maestro-agent` (authoring). Назначение: **внутренний стандарт ИБ** для
> разработчика скилла `maestro` — ориентир при принятии решений при развитии
> pipeline. Пользовательская документация — в `manual_docs/`.

## 1. Цель и область

Регламент доступа к данным и защита конфиденциальности в pipeline `maestro`.
Документ фиксирует модель доверия, требования ИБ и реализованные контрмеры, на
которые ссылаются спеки и планы при принятии решений.

## 2. Модель доверия

- **Оркестратор (primary-сессия) — НЕ доверен.** Доступ к `confidential/**` для
  него закрыт: плагин deny'ит root/primary (`plugins/maestro-bootstrap/core.js`,
  `resolveIsTrustedSubagent`: сессия без `parentID` → untrusted), инвариант
  конфига (`manual_docs/reference/config.md` → секция `confidential`).
- **Trust привязан к имени агента** (`maestro.json → trust`), не к модели. Модель
  — атрибут имени (`agent.*.model` в merge-конфиге: `.opencode/opencode.json` или global).
- **Fail-closed:** всё, чего нет в `trust` → untrusted; отсутствие `maestro.json`
  → все untrusted; primary/root, нерезолвнутый агент, ошибка lookup → untrusted.

## 3. Требования ИБ

- **P1.** Конфиденциальные данные (`docs/confidential/**`) — доступны только
  trusted-агентам по имени (`custodian`, `sanitizer`).
- **P2.** Проверка модели в рантайме НЕ требуется. Модель = атрибут имени;
  runtime-проверка циклическая (перечитывает значение из той же доверенной
  области — конфиг) и не защищает от компрометации конфига. Плагин fail-closed
  по имени. Решение принято 2026-08-24 (TODO #14).
- **P3.** При недоступности/ошибке модели trusted-агента — **запрещена подмена**
  `subagent_type`/модели для продолжения работы с конфиденциальным контекстом.
  Только HITL / ретрай той же пары `(subagent_type, задача)` / стоп. Авто-fallback
  на не-trusted агента/модель не существует и не допускается.
- **P4.** Гигиена конфига: trusted-агенты (`custodian`, `sanitizer`) — на
  локальной/изолированной модели; проверка доступности моделей через
  `@test-agents` перед пайплайном (TODO #23).
- **P5.** Плагин `maestro-bootstrap` обязателен (гейт на входе `/maestro`). При
  отключённом плагине защита fail-open — признанный риск (см. §5).

## 4. Реализованные контрмеры

- **Плагин `maestro-bootstrap`:** confidential deny (по имени/структуре сессии,
  fail-closed), sanitize промпта (Уровень 1, авто-маскирование), access_policy
  (HITL на `read`), аудит-лог.
- **Сабагент `sanitizer`** (trusted, read-only): Уровень 2 — пометки
  чувствительных данных перед untrusted-диспатчем.
- **HITL-гейты:** security review, file access control, гейт «плагин работает».

## 5. Известные ограничения

- **Не OS-барьер.** Защита — в плагине, не файловая (не chmod/ACL).
- **Fail-open без плагина.** При отключённом плагине confidential-доступ не
  ограничен — закрывается только гейтом (§4 P5).
- **Доверие по имени, не по модели.** Действует при нескомпрометированном конфиге.
- **Один уровень вложенности.** Trust не наследуется вложенными сабагентами.
- **P5-гейт — инструкция (не enforcement).** Жёсткий STOP исполняется
  оркестратором (LLM); нативного механизма «нет плагина → запретить» нет; обход
  гейта не покрыт тестами (осознанный scope).

## 6. Проверка инварианта

Инвариант «confidential deny не зависит от модели» — свойство кода плагина.
Регулярность привязана к событиям изменения/запуска, не к расписанию:

- **`npm test` — автоматическая (главная) проверка.** Прогон юнит-тестов при
  каждой правке кода плагина (`plugins/maestro-bootstrap/`). Детерминированно.
- **`@test-agents` — проверка по событию.** Перед стартом пайплайна и при смене
  моделей/провайдеров. Практический run-уровень: доступность моделей + primary
  deny при OK trusted-диспатча (в target-приложении с существующим
  `docs/confidential/**`).
- Cron-расписание не требуется: инвариант не деградирует сам, меняется только при
  правках кода (их покрывает `npm test`).
