> Дата: 2026-08-21. Репо: `maestro-agent` (authoring).
> Решение: модели агентов maestro можно настроить один раз в global-конфиге
> OpenCode (`~/.config/opencode/opencode.json`, ключ `agent.*`); все проекты,
> использующие скиллы maestro, наследуют их через merge-конфигурацию, а
> `maestro-init`/M1 при инициализации проекта учитывает global-агентов и
> предлагает наследование вместо повторного переспроса.

> «project → global → git-история → tier-подсказка» (эффективная модель =

## Постановка

Сейчас `/maestro-init` (M1) настраивает модели агентов **per-project**:
предложение формируется из текущего `opencode.json` → git-история →
tier-подсказка, без учёта global-конфига. Это приводит к повторному переспросу
моделей в каждом новом проекте, даже если пользователь уже настроил модели по
тирам один раз.

OpenCode **мержит** конфигурации, а не заменяет (docs opencode.ai/config).
Приоритет (позже переопределяет): remote → **global**
(`~/.config/opencode/opencode.json`) → project (`opencode.json`) → `.opencode/`.
Ключ `agent.*` задаётся в конфиге и наследуется на нижних уровнях. Значит,
настроив `agent.{design,haiku,sonnet,opus,fable,code-reviewer,sanitizer}` с
`model` (+ `temperature`) один раз глобально, можно централизованно применять
их во всех проектах; конкретный проект при желании переопределяет в project
`opencode.json`.

Чтобы централизация давала выигрыш, M1 должен видеть global-агентов — иначе
init в каждом проекте всё равно переспрашивает модели.

## Изменения

### 1. `skills/maestro-init/SKILL.md` — M1 учитывает global-агентов

Раздел «M1 — выбор моделей агентов» (строки 165-173):

- **Чтение (как D2, merge-представление):** M1 читает `agent.<name>.model` по
  уровням с merge-приоритетом `.opencode` > project > global; «текущий
  opencode.json» трактуется как **эффективное** значение (project, если задан
  в проекте, иначе global).
- **Шаг 2 (предложение):** приоритет → **project** `opencode.json` (если
  `agent.<name>.model` задан в проекте) → **global**
  (`~/.config/opencode/opencode.json`, наследуемая) → git-история →
  tier-подсказка. Иначе предлагалось бы значение, которое проект переопределяет.
- **Шаг 3 (варианты):** «оставить текущую» — если агент настроен **на любом
  уровне** (global или project); подпись уточняет источник («из проекта» /
  «из global»).
- **Шаг 4 (запись):** если выбрана «оставить из global» → **не писать** в
  project (наследование работает автоматически через merge); пишем только при
  выборе модели, отличной от эффективной, или ручном вводе.
- **Temperature:** при наследовании из global — не писать; при выборе новой
  модели для проекта — наследовать `temperature` из global (если задан),
  иначе писать дефолт по tier (не перезаписывать пользовательское значение).
- Сноска: централизованный вариант — настроить `agent.*` один раз в global;
  в новом проекте (без локальных моделей) M1 предложит «оставить из global»
  первым вариантом и не переспрашивать модельно.

### 2. `skills/maestro-init/init-context.md` — секция `opencode.json` → `agent.*`
