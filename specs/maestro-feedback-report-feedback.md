# Spec: дополнение maestro-feedback-report — пользовательский фидбек

> Статус: черновик для разработки. Дата: 2026-08-19.
> Репо: `maestro-agent` (authoring).

## Постановка

Команда `@maestro-feedback-report` генерирует отчёт по прошлым процессам maestro
в сессии, но не собирает обратную связь от пользователя по итогу — только
`(a) посмотреть/дополнить — (b) ок`. Пользователь может хотеть оставить
комментарии/рекомендации к отчёту.

**Цель:** добавить сбор пользовательского фидбека (комментариев) после генерации
отчёта, с записью в отдельную секцию отчёта.

## Архитектурное решение

**Два артефакта, разная ответственность:**

1. **Скилл `skills/maestro-feedback-report/SKILL.md`** — содержит логику сборки
   отчёта (шаги 1–4 из текущей команды). Используется сабэджентами и в новых
   задачах **без HITL** — для генерации отчёта автономно.
2. **Команда `commands/maestro-feedback-report.md`** — вызывает скилл (через
   `skill` tool), затем добавляет HITL-гейт для сбора фидбека от пользователя
   в консоли TUI. Только команда — с_HITL_.

**Почему разделение:** командой `@maestro-feedback-report` пользуется пользователь
сам и может участвовать в фидбеке. Скилл используется в сабэджентах — там HITL
невозможен/не нужен. Логика отчёта не зависит от HITL — выделение в скилл
делает её переиспользуемой.

## Изменения

> **Безопасность (TODO #1):** TODO.md #1 просит фиксировать проблемы безопасности
> касаемо чувствительных данных. В отчёт добавляется секция `## Безопасность` —
> агрегация sanitizer.access_policy событий из логов + упоминания безопасности
> из диалога (без деталей). При отсутствии событий — "Событий безопасности в
> текущей сессии не обнаружено."

### 1. Новый скилл `skills/maestro-feedback-report/SKILL.md`

Содержимое **текущей команды** `commands/maestro-feedback-report.md` (Шаги 1–4,
сбор фактуры и генерация отчёта) переносится в скилл.

Структура скилла:

```yaml
---
name: maestro-feedback-report
description: Сбор фактуры по прошлым процессам maestro для ретроспективы — генерация отчёта в .maestro/feedback-reports/
---
```

- Без HITL-гейта "посмотреть/дополнить — ок" (он остаётся в команде).
- В конце — просто: "Отчёт сохранён в `<путь>`".
- Поддерживает использование как сабэджентом (через `task` tool), так и
  оркестратором maestro.

### 2. Обновлённая команда `commands/maestro-feedback-report.md`

После вызова скилла — HITL-гейт (две ветки):

1. Показать выжимку: Session ID, дата, фичи, ключевые находки + секция безопасности
   (sanitizer.redacted / access_policy.blocked).
2. Спросить: «Нужно ли исправить фактуру?» →
   - Да: описать правку → перезапуск скилла + сохранение фидбека в перезаписанный отчёт
   - Нет: ввод рекомендаций/комментариев (Enter = пропуск)
3. Рекомендации → дописать `## Пользовательский фидбек` в конец отчёта.

**Важно:** HITL-запрос фидбека — **только в команде**, не в скилле. Точный текст
HITL-шага находится в команде (не дублируется в спеке, см. DRY).

### 3. Структура отчёта (расширенная)

Добавляется новая секция (появляется только при наличии фидбека):

```markdown
## Пользовательский фидбек
<комментарии пользователя>
```

Секция идёт последняя — после «Критические замечания» и «Безопасность». Не
создаётся, если пользователь пропустил запрос.

## Из НЕТ в scope

- Анализ самого фидбека (NLP, категоризация) — только запись текста.
- Интеграция фидбека в pipeline maestro — отдельная задача.
- Ретроспективные метрики на основе фидбека — future work.

## Открытые вопросы

- **Формат фидбека:** один общий комментарий или структурированный опрос?
  Решение: один общий комментарий (минимальное трение, пользователь решает
  сам как оформить). Если много комментариев — несколько строк/абзацев в одной
  секции.

- **Автокоммит фидбека:** тот же подход — автокоммит не требуется, `.maestro/`
  в gitignore.
