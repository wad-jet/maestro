# План: Требования и оценка ИБ (SECURITY.md) + синхронизация модели доверия

> Статус: **зафиксирован, реализация НЕ начата**.
> Дата: 2026-08-24. Репо: `maestro-agent` (authoring).

## Постановка

Зафиксировать **требования и оценку информационной безопасности (ИБ)** maestro
как единый источник истины (`SECURITY.md` в корне), на который ориентироваться
при принятии решений при развитии скилла. Документ — **внутренний стандарт ИБ
для разработчика**, не пользовательская документация (не входит в `manual_docs/`
Diátaxis).

Параллельно исправить рассинхрон модели доверия: в 2 местах оркестратор
(primary-сессия) описан как «доверенный», что противоречит и плагину
(`core.js:502` — deny root/primary), и уже зафиксированному инварианту
(`config.md:116-118` — primary/root → deny confidential).

## Зафиксированные решения

- **Проверка модели в рантайме НЕ требуется.** Trust привязан к **имени агента**
  (`maestro.json → trust`), не к модели. Модель — атрибут имени
  (`opencode.json → agent.{name}.model`). Runtime-проверка модели циклическая
  (перечитывает значение из той же доверенной области — конфиг) и не защищает
  от компрометации конфига. Плагин уже fail-closed по имени. Решение принято
  пользователем 2026-08-24 (TODO #14).
- Документ называется **`SECURITY.md`** — «Требования и оценка ИБ». Термин «ДИБ»
  (Департамент ИБ) НЕ используется.
- Расположение — корень репо (вариант A).
- `manual_docs/explanation/agents-and-trust.md` остаётся пользовательским
  документом и ссылается на `SECURITY.md`.
- Рассинхрон доков правится в этом же PR.
- Регулярное подтверждение инварианта «confidential deny не зависит от модели» —
  уровень 2, **вариант A** (логический инвариант, без принудительного слома
  модели): юнит-тесты + расширение `@test-agents`.

## Изменения

### 1. Создать корневой `SECURITY.md`

Преамбула: статус + дата + версия (как в спеках).

Структура:

1. **Цель и область** — регламент доступа к данным, защита конфиденциальности
   в pipeline maestro; ориентир при принятии решений.
2. **Модель доверия** (сводка принципов):
   - Оркестратор (primary-сессия) — **НЕ доверен**; confidential-доступ — deny
     (плагин `core.js:502`, инвариант `config.md:116`).
   - Trust привязан к **имени агента** (`maestro.json → trust`), не к модели.
   - Fail-closed: всё не-в-`trust` → untrusted; отсутствие `maestro.json` → все
     untrusted; primary/root, нерезолвнутый агент, ошибка lookup → untrusted.
3. **Требования ИБ** (нумерованные, ссылочные):
   - **P1.** Конфиденциальные данные — только trusted-агенты по имени.
   - **P2.** Проверка модели в рантайме НЕ требуется (обоснование выше).
   - **P3.** При недоступности модели trusted-агента — запрет подмены
     `subagent_type`/модели; только HITL / ретрай той же пары / стоп.
   - **P4.** Гигиена конфига: trusted-агенты (`design`, `sanitizer`) — на
     локальной/изолированной модели; проверка доступности моделей через
     `@test-agents` перед пайплайном (TODO #23).
   - **P5.** Плагин обязателен (гейт); при отключённом — fail-open, признанный
     риск.
4. **Реализованные контрмеры** — плагин (confidential deny, sanitize Ур.1,
   access_policy, аудит-лог), sanitizer (Ур.2), HITL-гейты.
5. **Известные ограничения** — не OS-барьер, fail-open без плагина, доверие по
   имени, один уровень вложенности (trust не наследуется), **P5-гейт — инструкция
   (не enforcement)**: жёсткий STOP исполняется оркестратором (LLM), нативного
   механизма «нет плагина → запретить» нет; обход гейта не покрыт тестами
   (осознанный scope).
6. **Открытые вопросы / roadmap ИБ** — ссылки на TODO: #14 (модели trusted),
   #23 (изолированная модель), #50 (миграция через confidential).

### 6. Регулярное подтверждение инварианта (уровень 2, вариант A)

**6a. Юнит-тесты `index.test.js`** (детерминированные, в `npm test`), секция
«confidential enforcement»:

- Кейс B: trusted-агент allow не сохраняет состояние — после успешного read
  trusted (`childTrusted`) повторный read из `root` → всё равно deny
  (доступ per-call по сессии, не «размораживается»). Регрессионный guard против
  будущего введения кеша/размораживания доступа.
- Кейс A НЕ добавляется: «primary denied при lookup-ошибке сессии» уже
  покрыто существующим тестом `index.test.js:1041-1046`
  (`denies on session lookup error (fail-closed)`) — дублировать нечего.

**6b. Расширение `commands/test-agents.md` (`@test-agents`):**

- **Предусловие:** команда рассчитана на **target-приложение** с существующим
  `docs/confidential/**` (создаётся `/maestro-init`). В authoring-репо
  `docs/confidential` отсутствует — там 6b не исполняется.
- После основной таблицы OK/FAIL для 7 агентов:
  - Для trusted (`design`, `sanitizer`) — задача «прочитай `docs/confidential/...`»
    (дефолтный путь, конфиги не читать).
  - Затем read того же файла из primary-сессии.
  - Зафиксировать: primary read → всегда deny при **OK** trusted-диспатча
    (логический инвариант, вариант A).
  - **Ограничение (честно):** ветка **FAIL** (модель trusted реально недоступна)
    в варианте A детерминированно не эмулируется — она воспроизводится только
    при фактической недоступности модели и в штатном прогоне не проверяется.
    Принудительный слом модели (временная правка `opencode.json`) — вариант B,
    отклонён пользователем.
  - Результат — отдельная строка в сводке: «confidential-invariant: primary deny
    при OK trusted-диспатча».

**6c. `SECURITY.md`, секция «Проверка» — регламент регулярности:**

Инвариант «confidential deny не зависит от модели» = свойство кода плагина.
Регулярность привязана к **событиям изменения/запуска**, а не к расписанию:

- **`npm test` — автоматическая (главная) проверка.** Прогон юнит-тестов (6a)
  при **каждой правке кода плагина** (`plugins/maestro-bootstrap/`) — при
  разработке, на ревью, перед PR/commit. Детерминированно, быстро; это
  единственный по-настоящему регулярный (автоматический) гарант инварианта.
- **`@test-agents` — проверка по событию.** Перед **стартом пайплайна**
  (вход `/maestro`) и при **смене моделей/провайдеров** (миграция, переконфиг
  `opencode.json`, новый провайдер). Практический run-уровень: реальный диспатч
  + подтверждение, что primary deny работает (6b).
- Расписания (cron) **не требуется**: инвариант не деградирует со временем сам,
  а меняется только при правках кода — их и покрывает `npm test`. `@test-agents`
  закрывает событийные точки (доступность моделей, смена провайдера).
