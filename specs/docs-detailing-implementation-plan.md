### П.28 — D2: упрощение определения доступных моделей (Q2, Вариант 2)

**Файлы:** `skills/maestro-init/SKILL.md` (D2), `manual_docs/tutorials/setup-project.md`
(раздел D2), `manual_docs/reference/model-selection.md`, `manual_docs/reference/config.md`.

**Действие — инверсия порядка источника моделей (P1):**
- **Основной источник** доступных моделей — `opencode models <provider>` (спрашивает
  рантайм opencode, не читает глобальный конфиг). Текущий `provider.models` из
  merge-конфига перестаёт быть основным.
- **Fallback** (по приоритету): если `opencode models` недоступна/пуста/ошибка →
  эффективный merge-конфиг (`provider.models`, project → global) → ручной ввод.
- Согласовать во всех местах (SKILL.md D2, setup-project.md D2, config.md D2).

**Перебор провайдеров (P2):** команду `opencode models <provider>` выполнять для
**каждого провайдера**, зарегистрированного в эффективном merge-конфиге (ключи
`provider.*`), объединяя списки моделей. Если провайдеров в конфиге нет — fallback
на ручной ввод / известный провайдер.

**Триггеры fallback (P3, явно):** `opencode models` недоступна как команда /
возвращает ошибку / пустой список → переключение на merge-конфиг → затем ручной
ввод.

Устраняет «странное» обращение к глобальному файлу при настройке opencode.
Документацию D2 обновить под новую логику.
