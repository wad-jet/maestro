# Spec: уход от агента `maestro`, оставить только скилл

> Статус: черновик для разработки. Дата: 2026-08-18.
> Репо: `maestro-agent` (authoring). Масштаб: архитектурный рефакторинг.

## Постановка

Полностью уйти от агента `maestro` (primary). Оставить только скилл `maestro`
как единственный механизм orchestration. Вход в pipeline — через команду
`@maestro` в любой primary-сессии. Плагин `maestro-bootstrap` перестаёт
опираться на агента `maestro` (инжекция директивы и фильтрация по агенту
удаляются), становится глобальным (санитайзинг task-промптов + минимальный
аудит-лог + обработка ошибок).

## Цели

1. Убрать зависимость orchestration от агента `maestro`.
2. Единый вход — команда `@maestro`, работающая в любой primary-сессии.
3. Плагин работает глобально, без привязки к агенту.
4. Сохранить (или усилить) защиту чувствительных данных субагентов (sanitizer).
5. Синхронизировать документацию (SKILL, manual_docs, AGENTS, README).

## НЕ входит в scope

- Реализация sanitizer в плагине (функция `sanitize` + whitelist + аудит-лог) —
  **отдельная** задача (см. `security-review-plan.md`, раздел «Этап 2»).
  Здесь только убираем агента и пересматриваем роль плагина (инжекция /
  observability). Sanitizer добавляется в своей задаче.

## Текущее состояние

- Вход: агент `maestro` (primary, `agents/maestro.md`), загружает скилл на шаге 1.
- Команды `@regression`, `@maestro-init` привязаны к `agent: maestro`.
- `@test-maestro` проверяет доступность агента `maestro`.
- Плагин `maestro-bootstrap`: инжекция директивы (фильтр `agent === "maestro"`),
  observability (логирование tool-calls maestro-сессий), `agentBySession`-маппинг.
- SKILL.md: модель оркестратора = агент maestro.

## Целевое состояние

### Вход

- Новая команда `commands/maestro.md` (`@maestro`): в любой primary-сессии
  инструктирует «загрузи skill maestro и следуй pipeline». Поле `agent:` — без
  привязки к конкретному агенту (generic). Это единственная точка входа.
- `agents/maestro.md` — удалить.
- `commands/test-maestro.md` — удалить (агента больше нет).
- `commands/regression.md`, `commands/maestro-init.md` — убрать `agent: maestro`
  (работают в любой сессии).

### Плагин `maestro-bootstrap`

Новая роль: **глобальный** (не привязан к агенту).

| Функция | Было | Стало |
|---|---|---|
| Bootstrap-инжекция | Директива в сессии агента `maestro` | **Убрать** (вход — команда `@maestro`) |
| Observability | Логирование tool-calls maestro-сессий | **Сократить**: `task`-диспатчи (аудит-лог) + ошибки |
| Sanitizer (Ур.1) | — | **Добавить** (глобальный санитайзинг task-промптов) — в своей задаче |

- Удалить `experimental.chat.messages.transform` (инжекция).
- Удалить `agentBySession`-маппинг и фильтрацию `agent === "maestro"`.
- Логирование: оставить `session.error`, `session.status.retry` (глобально),
  `tool.execute.after.empty_result` (глобально). Убрать детальное
  `tool.execute.before/after` для bash/skill (оставить task-аудит в задаче sanitizer).

### SKILL.md

- Модель оркестратора: не агент, а скилл в primary-сессии. Обновить упоминания
  агента maestro, команду входа (`@maestro`), шаг 1 (загрузка скилла).

### Документация

- `manual_docs/`, `AGENTS.md`, `README.md`, `plugins/maestro-bootstrap/README.md` —
  синхронизация (агент удалён, вход через `@maestro`, плагин глобальный).

## Решения

- Вход — команда `@maestro` (в любой сессии), не скилл напрямую.
- Команды `@regression`/`@maestro-init` работают в любой сессии (убрать `agent:`).
- `@test-maestro` удаляется (агента нет); остальные `@test-*` для субагентов остаются.
- Плагин: инжекция убирается, observability сокращается до task-аудита + ошибок.
- Sanitizer в плагине — отдельная задача (Этап 2), не в этом spec.
