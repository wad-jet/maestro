# Классификация фич

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Справочник категорий фич и матрицы сигналов, по которой оркестратор назначает
категорию на шаге 7 (braingate: выгрузка контекста).

## 📖 Категории

| Категория | Примеры | Pipeline | Spec Review | SDD | Модель SDD |
|---|---|---|---|---|---|
| **Trivial fix** (1–2 строки) | Typos, rename, single-line bugfix | TDD + commit напрямую; pipeline не запускается | Нет | Нет | — |
| **Простая фича** | Simple endpoint, UI-компонент без стейта, добавление поля в DTO | Шаги 2-7 → план (11-12) → SDD (13) | Нет | 1-2 task без review-package | **Haiku** |
| **Сложная фича** | Новая сущность с миграцией, multi-step flow, endpoint с auth | Полный pipeline: 2-7 → spec (8) → опц. Spec Review (9) → gate (10) → план (11-12) → SDD (13) | Рекомендован | Multi-task, review-package | **Sonnet** (**Opus** для key task) |
| **Архитектурная фича** | Новая таблица + сервис + контроллер, breaking change, cross-module refactoring | Полный pipeline + обязательный Spec Review | **Обязателен** | Multi-task, redesign после review если `revise` | **Opus** |

## 📖 Матрица сигналов

| Сигнал | Простая | Сложная | Архитектурная |
|---|---|---|---|
| Сколько файлов? | 1-2 | 3+ | 5+ |
| Миграция БД? | Нет | Опционально | Да (таблица / NOT NULL) |
| Public API? | Нет | Да | Да (breaking change) |
| Breaking change? | Нет | Нет | Да |
| Новый модуль? | Нет | Опционально | Да |
| Cross-layer change? | Нет | Да (≥3 слоя) | Да |
| Cross-service change? | Нет | Да (при ≥3 файлов) | Да (при cross-layer) |

> Если хотя бы один сигнал попадает в «Сложная» или «Архитектурная» — фича
> **не** считается простой, и шаги 8–10 (spec + опциональный Spec Review)
> выполняются.

> **Быстрый триггер (fast trigger).** Если итоговый диф можно описать одним
> предложением, фича классифицируется как простая (Bounded) без применения
> матрицы. Триггер НЕ переопределяет сигналы колонки «Архитектурная» и строку
> «Public API»: если есть хотя бы один такой сигнал, применяется полная матрица.

## 📖 Почему это важно

Простая и сложная фича — это не просто объём работы, а разные уровни риска для
кодовой базы:

| Аспект | Простая | Сложная |
|---|---|---|
| **Spec** | 3 предложения в user story достаточно | Без spec архитектурная ошибка обнаружится на code-review — дорогой реверс |
| **Spec Review** | Избыточен — ошибка ограничена 1–2 файлами | Ловит проблемы до строки кода. Стоимость review << стоимости переписывания |
| **SDD model tier** | **Haiku** хватает — механическая трансляция spec → код | **Sonnet+** нужен для multi-file coordination. **Haiku** медленнее из-за лишних туров |
| **Откат** | Легко — 1–2 файла, `git revert` | Тяжело — миграции, breaking changes, каскадные изменения |
