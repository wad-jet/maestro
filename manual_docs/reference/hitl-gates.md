# Справочник HITL-гейтов

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Полный перечень HITL-гейтов в pipeline скилла `maestro` и вариантами ответов.
Decision gates (шаги 2, 7, 10, 12, 17) — явный вопрос с вариантами (a)/(b)/(c),
сопровождаемый рекомендуемым дефолтом (п. 4а).

## 📖 Протокол

1. **Язык:** все вопросы и варианты — только на русском.
2. **Показать контекст** перед вопросом (diff, список задач, git log).
3. **Задать структурированный вопрос** (a)/(b)/(c), не «Continue?».
4. **Дождаться ответа** — молчание ≠ approval.
4а. **Дефолты на decision gates (P1.3):** вопросы (a)/(b)/(c) на шагах 2, 7, 10,
    12, 17 сопровождаются рекомендуемым вариантом с обоснованием
    («рекомендую (a) X, потому что Y»). Подтверждение — только явной буквой;
    «continue»/«давай» дефолт НЕ подтверждают (п. 3). Прочие гейты (0, 1, 1.5,
    D2/D6/D7, плато/особый случай шага 10, security-гейты) — без дефолтов.
    Если условие-источник не выполнено — дефолт не предлагается.
5. **После ответа:** Approve → следующий шаг · Revise → назад · Reject → STOP.
6. **Правило вопросов (UX):** свободный текст и содержательные выборы — обычным
   текстовым вопросом (не панель/select); вопрос-инструмент (панель) — только
   для быстрых формальных выборов из фиксированного набора. Связанные
   дизайн-решения и связанные правки (revise-цикл) — пакетами по 3-4 в один
   HITL-блок, не по одной.

> ⚠️ «Continue» / «Proceed» / «Давай» / «Внеси правки» **не** являются approval для
> последующих гейтов (и не команда на реализацию). Ответ переводит pipeline ровно
> на один шаг; следующий гейт требует отдельного ответа. Комментарии по содержанию
> спеки применяются к спеке (revise-цикл 10b), не к коду.

## 🚀 Режимы запуска (`@maestro-init`)

Режим задаётся флагом при вызове `@maestro-init`, per-run (не персистится):
`--auto-answer`/`-aa` · `--auto-ai`/`-ai` · без флага / `--no-auto` — manual.

**Инварианты автоматизации (все режимы):** ⚑1 PR/мерж — только человек (гейт 17);
⚑2 финальное ревью спеки — только разработчик, принятие — только явная команда
(гейт 10); ⚑3 ИИ-тесты не полностью доверены; ⚑4 внешние API-контракты интеграций
и основополагающие правила бизнес-логики — только явное HITL-решение.

Канон инвариантов — `skills/maestro/invariants.md` (поставляется со скиллом).

| Гейт | manual | auto-answer | auto-ai |
|---|---|---|---|
| 0 — контекст | HITL | авто (a) загрузить, если файл есть; нет → HITL | авто |
| 1 — маршрут | HITL | авто из текста задачи, если однозначно | авто |
| 1.5 — режим | HITL | авто (a) efficient | не спрашивается |
| 2 — pre-flight | HITL | авто (a) да (P1.3) | авто |
| 7 — категория | HITL | авто по матрице (P1.3) | авто |
| 7d — внешний spec | HITL | авто (d) при однозначном соответствии | авто |
| 9 — Spec Review offer | HITL | авто (b) прогнать (сложные) | авто (по анализу; архитектурные — обязателен) |
| 10 — spec gate | **HITL (⚑2): явная команда** | **HITL (⚑2): явная команда** | **HITL (⚑2): явная команда** |
| 12 — plan gate | HITL | авто (a) при P1.3 + guard ⚑4 | авто; чувствительные → HITL (⚑4) |
| 17 — pre-PR/merge | **HITL (⚑1)** | **HITL (⚑1)** | **HITL (⚑1)** |
| Контентные вопросы (brainstorm, custodian, D2/D6/D7, имя ветки, spike) | HITL | HITL | авто (доп. анализ) |
| Security-гейты (8.6, Точка 2, P5) | HITL | HITL | гибрид: только risk-reducing дефолты сам; риск/стоп — HITL |
| Чувствительные изменения ⚑4 | HITL | HITL | HITL |
| Tier 3 / падение команд (15/15a), docs-расхождения (14), reconciliation (13f) | HITL | HITL | HITL |

Правило P1.3: если условие-источник рекомендации не выполнено — вопрос остаётся
HITL в любом режиме. Каждое авто-принятие в auto-answer выводится строкой
`[auto-answer] шаг N: …` (не молча).

**auto-ai — как ИИ решает.** Механические авто-принятия и risk-reducing
security-дефолты применяет оркестратор сам (источник-условие). Сужденческие
вопросы (маршрут при неоднозначности, контентные вопросы, D2/D6/D7, Spec Review
offer, docs-шаг) — диспатч батчами через `auto-ai-decision-prompt.md`: `sonnet`
(средние) / `opus` (сложные), эскалация sonnet→opus, при неуверенности —
консервативный выбор (более полный путь). Журнал решений + сводка на гейтах
10/17. Security-гибрид — только risk-reducing; риск/стоп — HITL. Ralph loop ведёт
цикл до `<promise>DONE</promise>`, но не форсирует гейты 10/17 (жёсткие паузы).

## 📖 Гейты feature-маршрута

| Шаг | Гейт | Варианты |
|---|---|---|
| 0 | Загрузка Project Context | (a) загрузить/подтвердить · (b) создать/обновить · (c) пропустить · (d) отмена |
| 1 | Маршрут | (f) feature · (b) bugfix · (s) spike · (c) отмена |
| 1.5 | Режим | (a) efficient · (b) interactive · (c) отмена |
| 2 | Подтверждение старта (pre-flight) | (a) да · (b) отмена · (c) skip → D1 в interactive |
| 7 | Категория фичи | (a) сложная/архитектурная · (b) простая (Bounded) · (c) отмена · при (a) — fast-track: (d) использовать внешний spec · (e) создать заново (шаг 8) |
| 8.6 | Spec security review (при находке sanitizer) | (a) вычистить и продолжить · (b) продолжить как есть (принять риск) · (c) стоп |
| 10 | Spec утверждён | (a) Approve · (b) Revise → правки opus, оркестратор применяет (Ур.1), повторный review · (c) Reject |
| 10 | Особый случай Revise (правке нужен confidential) | (a) trusted `custodian` (Q/A-агрегат) · (b) follow-up · (c) отмена |
| 10 | Сходимость Revise — fast-path (контрольное ревью закрыло все Critical/Important, только Minor → дефолт (a) Approve, Minor → follow-up) · плато (2 раунда без новых Critical/Important при незакрытых повторах) | (a) Approve · (b) продолжить ещё · (c) follow-up оставшиеся |
| 12 | Plan утверждён | (a) Approve · (b) Revise → шаг 11 · (c) отмена |
| 17 | Pre-PR | (a) Approve merge · (b) Fix → шаг 13 · (c) отмена. Gate показывает список открытых issues (open + follow-up) с severity из шага 16; если открытых нет — (b) помечается «только follow-up, не блокирует». **«Test results»** — фактический вывод `$TEST_COMMAND`: команда, exit code, summary-строки (например `tests 173, pass 173, fail 0`), а не утверждение «тесты прошли». Если тесты не выполнялись в текущей сессии — оркестратор выполняет их до гейта; исключение — осознанный пропуск на шаге 15 (багфикс probe==fix / low-risk фича ≤2 файла): вместо вывода «Тесты пропущены на шаге 15 (low-risk), coverage = <N%>». **E2E-критерии приёмки** (если в спеке): на гейте показывается «прогнаны: <результат>» или «пропущены, риск принят: <обоснование>»; merge при пропуске — явное HITL-решение. |

## 💡 Особые случаи

- **Spec Review (шаг 9):** оркестратор обязан предложить его для сложных фич;
  для архитектурных — обязателен, отказаться нельзя. Шаг 10 не наступает, пока
  пользователь не ответил. Spec написан primary (шаг 8, brainstorm + custodian Q/A);
  перед диспатчем opus (untrusted) spec проходит security review (шаг 8.6).
- **Revise (шаг 10b):** правки даёт `opus` (untrusted, `edit: deny`), применяет
  оркестратор (Ур.1). Повторный 8.6 — только при вовлечении trusted-контура.
  Если правке нужен confidential → HITL: (a) custodian / (b) follow-up / (c) отмена.
- **Fast-track (шаг 7d):** внешний spec вместо дизайна (шаг 8). Для всех
  7d-входов подпись — рекомендация, не авто-пропуск: sanitize (8.6) выполняется
  всегда (кроме HITL-заверения при валидной `CLEAN`), ревью (9) предлагается
  всегда через HITL — (a) пропустить / (b) прогнать. Отсутствие подписи не
  блокирует вход.
- **Trivial fix (1–2 строки):** maestro не используется — redirect на `@haiku`.

## 📋 Anti-loop: лимит повторов

> **Повтор после Revise (anti-loop): не более 1 повтора.** В отличие от budget
> повторов 3 для проверки доступности модели (SKILL.md → «Недоступность модели
> trusted-агента», пункт (b)), повтор после `revise`-вердикта spec-ревью
> ограничен **одним** повтором для пустого/бессодержательного результата (как
> и любой пустой/бессодержательный результат диспатча) — чтобы не допустить
> бесконечный цикл. См. [SKILL.md](../../skills/maestro/SKILL.md).
>
> **Отмена/прерывание диспатча ≠ отказ от ревью:** обязательное ревью возобновляется
> пере-диспатчем; единственный выход без прохождения — отмена фичи целиком
> (отдельных «скип-ответов» для обязательных ревью не существует).
