# Выбор и замена модели эмбеддингов

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Как выбирать, настраивать и заменять модель эмбеддингов memory layer
(`memory.embedding_model` / `memory.embedding`). Методика + механика; справочник
ключей — [Память maestro (reference)](../reference/memory.md) и
[Конфигурация (reference)](../reference/config.md).

## 📖 Критерии выбора

| Ось | Локальная (transformers.js) | Внешняя (OpenAI-совместимый API) |
|---|---|---|
| Качество recall | MiniLM-384 (RU+EN); слабее крупных провайдерских | text-embedding-3, multilingual-e5 и т.п. — обычно выше |
| Размерность | **384** (фиксирована для local; модель обязана быть 384-мерной) | **конфигурируемая** (`embedding.dim`, обязателен; равен нативной размерности модели) |
| Инференс | Локальный CPU/WASM, без сетевых задержек; загрузка модели один раз | Сетевой вызов на каждый embed (есть in-memory кэш повторных запросов); задержка + rate-limits |
| Offline | Работает офлайн после однократной загрузки (~120 МБ кэш) | Нет: каждый embed — сетевой вызов |
| Приватность | Данные не покидают машину | Контент записей маскируется; recall-запросы маскируются всегда (best-effort); данные уходят провайдеру — осознанный opt-in (init-warn при confidential.paths) |
| Стоимость | 0 (локальный CPU/WASM) | Токены + rate-limits |
| Командная совместимость | dim фиксирована (384), но модель входит в `model_id` — смена требует переиндексации; в команде — одна модель для всех | `model_id` = `openai:<model>@<base_url>`; в команде — одна модель/URL/dim для всех |

## 📖 Рекомендуемые модели

Проверенные варианты под типовые сценарии. «Offline» — работает после однократной
загрузки кэша (local) / требует сети на каждый вызов (внешняя).

| Модель | Провайдер | dim | RU+EN | Offline | Нагрузка/стоимость | Когда использовать |
|---|---|---|---|---|---|---|
| `Xenova/paraphrase-multilingual-MiniLM-L12-v2` (**default**) | local | 384 | ✅ | ✅ | ~120 МБ, 0 | Память по умолчанию: личная, offline/privacy-first; достаточно для большинства задач |
| `Xenova/multilingual-e5-small` | local | 384 | ✅ | ✅ | ~120 МБ, 0 | Локальная альтернатива дефолту с чуть более сильным recall (e5-семейство), та же dim 384 |
| `text-embedding-3-small` | openai | 1536 | ✅ | ❌ | низкая | Внешний embedder; нужны сеть и ключ; заметно выше качество recall |
| `text-embedding-3-large` | openai | 3072 | ✅ | ❌ | средняя | Максимальное качество recall; бюджет позволяет |

> ⚠️ **Смена модели всегда требует переиндексации — даже при одинаковой dim.**
> Например, замена одной local-модели dim 384 на другую: `model_id` различается,
> вектора несовместимы (см. [Память maestro (reference)](../reference/memory.md) —
> `model_id` в метаданных, инструкция переиндексации). Исключений нет.

> Для внешних моделей `embedding.dim` обязателен и должен равняться **нативной**
> размерности модели (без Matryoshka-усечения) — иначе dim-mismatch hard-fail.

## 📖 Как настроить

Локальная (default):

```json
{ "memory": { "enabled": true, "embedding_model": "Xenova/paraphrase-multilingual-MiniLM-L12-v2" } }
```

или через блок (эквивалентно):

```json
{ "memory": { "enabled": true, "embedding": { "provider": "local", "model": "Xenova/paraphrase-multilingual-MiniLM-L12-v2" } } }
```

Внешняя:

```json
{
  "memory": {
    "enabled": true,
    "embedding": {
      "provider": "openai",
      "model": "text-embedding-3-small",
      "base_url": "https://api.openai.com/v1",
      "api_key_env": "MAESTRO_MEMORY_EMBED_KEY",
      "dim": 1536
    }
  }
}
```

Правила: `api_key_env` — имя env-переменной, никогда plaintext; `dim` обязателен
и равен **нативной** размерности модели (Matryoshka-усечение не поддерживается);
`base_url` — любой OpenAI-совместимый `/embeddings` (OpenAI, LiteLLM/one-api,
vLLM); trailing-slash нормализуется.

## 📖 Как сменить модель и переиндексировать

Смена модели/провайдера → **переиндексация** (вектора старой модели несовместимы
с новой; другой `model_id`). Пошагово:

### Шаг 0: согласовать модель (командный сценарий)

Если хранилище **общее** (qdrant/pgvector) — смена модели влияет на всех
разработчиков. Согласуйте единую модель/`dim` со всей командой **до** начала
переиндексации (см. [Командный сценарий](#командный-сценарий-shared-хранилище)).

### Шаг 1: проверить текущую модель

`@maestro-memory` → строка «Модель: …» (для внешней — `openai:<model>@<base_url>`).

### Шаг 2: обновить конфиг

В `maestro.json` секция `memory`: новая модель через `embedding_model` (local) или
`embedding.model` + `provider`/`base_url`/`api_key_env`/`dim` (внешняя).

### Шаг 3: удалить данные памяти старой модели

| Бэкенд | Что удалить |
|---|---|
| `sqlite` | `<data-dir>/maestro/memory/<hash>/` (файл `memory.db`) |
| `qdrant` | коллекцию (ключ `storage.qdrant.collection`) |
| `pgvector` | таблицу (ключ `storage.pgvector.table`) |

`<data-dir>`: `$XDG_DATA_HOME` → macOS `~/Library/Application Support` →
`~/.local/share`. Полный перечень границ удаления — [Как включить память](enable-memory.md).

### Шаг 4: сбросить состояние индексации и перезапустить

**Обязательно** удалить `<data-dir>/maestro/memory/state.json` (retry/skip/first-run
состояние): в нём живёт `lastSummarized` — иначе уже проиндексированные старой
моделью сессии (без 3+ новых сообщений) будут **молча пропущены** backfill'ом и
не пере-эмбеддятся новой моделью.

Затем перезапустить opencode — начнётся **backfill** (пере-индексация сессий
новой моделью).

### Шаг 5: проверить

`@maestro-memory` показывает новую модель; `memory_probe` — live-проверка
embedder (минуя cooldown).

## 🌐 Командный сценарий (shared-хранилище)

В общей команде на qdrant/pgvector **все разработчики обязаны использовать одну
модель и `dim`** — иначе вектора несовместимы и recall **молча портится** (без
ошибки). Это известное ограничение бэкендов: «разные модели в одной коллекции →
мусорное ранжирование», см. [Память maestro (reference)](../reference/memory.md).

Координация смены модели:

- смена — **единое согласованное действие**: один ответственный удаляет
  коллекцию/таблицу, все участники обновляют конфиг и перезапускают;
- **несинхронная смена** = разъехавшиеся `model_id` → тихая деградация recall у
  всей команды.

## ⚠️ Чек-лист ошибок

- `memory_export` → `memory_import` между **разными `model_id`** — не сработает:
  валидация атомарно отвергнет файл (перенос работает только при совпадающей
  модели/`dim`; миграция данных между моделями не поддерживается).
- **dim-mismatch** (внешний embedder): `embedding.dim` ≠ нативной dim модели →
  hard-fail на probe (память off).
- **Несовпадение модели на бэкенде** → для `sqlite` ошибка с инструкцией
  переиндексации (мета-проверка на init, без тихой порчи данных). На
  shared-бэкендах (qdrant/pgvector) с равной `dim` mismatch не детектируется —
  см. [Командный сценарий](#командный-сценарий-shared-хранилище).

## 📖 Проверка доступности

`@maestro-memory` → строка «Проверка embedder» (последний статус) или tool
`memory_probe` (live, минуя cooldown). При `FAIL (конфигурация)` — исправить
конфиг и перезапустить opencode (авто-перепроверка на старте). Внешний
провайдер проверяется при старте не чаще `probe_cooldown_min` (default 30 мин).
