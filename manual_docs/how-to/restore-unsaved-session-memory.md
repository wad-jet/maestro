# Память сессии не сохранилась — как восстановить

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Восстановить запись сессии в памяти, которая не попала в хранилище из-за
сбоя индексации (недоступное хранилище, embedder, или внутренняя ошибка).
Данные самой сессии в opencode целы — запись пересаммаризируется заново.

## ✅ Шаг за шагом

1. **Посмотреть масштаб:** запустите `@maestro-memory` — блок
   «Не индексированные сsessionи: N» покажет сколько сессий затронуто,
   с reason-классом и флагом skip.

2. **Восстановить:** запустите `@maestro-memory-reindex` → укажите
   `action: "run", source: "sessions", session_ids: "<id из уведомления>"`.
   Запись пересаммаризируется (LLM-затраты: один summarize на сессию)
   и запишется в хранилище; permanent-skip сбросится.

   Можно восстановить все сразу — `all_empty: true` — но это затронет
   и сессии, которые просто ожидают обработки. Для целевого восстановления
   укажите конкретные session_id.

3. **Проверить результат:** `@maestro-memory` — «Не индексированные сессии»
   должно уменьшиться (или стать 0). Запись появится в `memory_search`
   и авто-recall.

## ⚠️ Статусы восстановления

| Статус | Значение |
|---|---|
| `indexed` | Запись восстановлена успешно |
| `unattributed` | Сессия без git-head — запись создана без ветки |
| `no_new_messages` | В сессии недостаточно новых сообщений для саммаризации |
| `not_found` | Сессия не найдена в opencode |
| `skip_service` | Служебная сессия (авто-пропуск) |
| `failed: storage_error` | Хранилище всё ещё недоступно — восстановить доступ и повторить |
| `failed: embedder_error` | Embedder недоступен — проверить конфиг/сеть/ключ |
| `failed: index_error` | Внутренняя ошибка индексации — перезапуск opencode |

Если статус `failed: <класс>` — проблема всё ещё актуальна. Восстановите
причину (URL/ключ/сеть) и повторите индексирование. Перезапуск opencode
также позволяет повторить индексирование, пока сессия не ушла в skip.
