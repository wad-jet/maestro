# Как включить учёт стоимости сессий (cost tracking)

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Пошаговое объявление цен моделей в конфиге opencode, чтобы **opencode нативно
считал стоимость сессии** и она отображалась:

- в **TUI opencode** (стоимость в данных сессии);
- в **feedback-отчёте maestro** (`@maestro-feedback-report`, секция «Итоговая
  статистика» - колонка «Стоимость» в таблице агентов, `cost` в строке
  primary и строка «Итого (primary + агенты)»).

Механизм полностью нативный для opencode: цены объявляются в конфиге opencode
(блок `provider.<id>.models.<name>.cost`), opencode считает cost по
потреблению токенов. В репо maestro и в плагине **нет сети, ключей и прайс-карт** -
отчёт только агрегирует уже рассчитанный opencode cost (`metrics.cost`).
Модель без объявленных цен - «дефис» в отчёте (не ошибка).

## ✅ Краткая инструкция

1. Открыть конфиг opencode: глобальный `~/.config/opencode/opencode.json` или
   проектный `<проект>/.opencode/opencode.json` (проектный дополняет/переопределяет
   глобальный).
2. Для каждой используемой модели добавить блок `cost` внутри
   `provider.<id>.models.<name>` (пример для openai-совместимого провайдера,
   кастомный provider с npm `@ai-sdk/openai-compatible`):

   ```json
   "provider": {
     "myprovider": {
       "models": {
         "vendor/model-x": {
           "cost": { "input": 0.225, "output": 1.98, "cache_read": 0.05 }
         }
       }
     }
   }
   ```

   Формат цен - **доллары за 1M токенов** (формат models.dev):

   | Поле | Значение |
   |---|---|
   | `input` | цена input-токенов (обязательно) |
   | `output` | цена output-токенов (обязательно) |
   | `cache_read` | цена чтения кэша (опционально) |
   | `cache_write` | цена записи в кэш (опционально) |

   > Блок `cost` вставляется в существующую запись модели; остальные поля
   > провайдера/модели (npm, name, options и т.д.) не меняются.
3. **Перезапустить opencode** (конфиг читается при старте).
4. Проверить: в новой сессии TUI показывает стоимость; в feedback-отчёте
   maestro `metrics.cost` заполнен, колонка «Стоимость» и строка
   «Итого (primary + агенты)» содержат суммы.

## 📖 Где взять цены

- **Прайсинг-страница/гайд провайдера** (model card, pricing page) - основной
  источник.
- **API провайдера:** `GET /v1/models` (если провайдер возвращает цены) -
  per-token цена × 1e6 = цена за 1M токенов.
- **models.dev** - каталог цен на модели (тот же формат $/1M).

## 🔍 Эффект

- **TUI opencode:** cost появляется в данных сессии (per-message и сумма),
  отображается в интерфейсе.
- **Feedback-отчёт maestro:** `metrics.cost` заполнен
  (`available: true`, `primaryUsd`, `byAgent`, `totalUsd`, `note`), секция
  «Итоговая статистика» - колонка «Стоимость» в таблице агентов,
  `cost: $X.XX` в строке primary, строка «Итого (primary + агенты)».
- **Модель без блока `cost`** - «дефис» в колонке/строке; если cost нет ни
  у primary, ни у агентов - `metrics.cost.available: false`, сумм нет.

## 🛠️ Обновление цен

При смене прайса провайдера - **поправить конфиг вручную** (блок `cost` у
соответствующей модели) и перезапустить opencode. Автообновления цен нет
(осознанно: сеть и внешние источники в плагине/репо не используются).
