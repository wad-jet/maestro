# Настройка restricted-путей

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Как менять набор restricted-путей (конфиденциальных данных) в проекте
maestro: добавить/расширить/снять с защиты. В new-режиме (6.4.0)
**источник** restricted-путей — нативные permissions OpenCode
(merge-config); секция `confidential` в `maestro.json` не генерируется
(legacy-режим — только до миграции).

**Одна операция** пишет обе части: источник (нативные deny) и зеркало
(строка §12 в `docs/project-context.md`). Добавление пути — усиление
защиты, выполняется консервативно; снятие с защиты — жёсткий блок по
умолчанию.

## 📖 Предпосылки

- Конфигурация maestro: `/maestro-assistant` (канон —
  `skills/maestro-assistant/SKILL.md`, воркфлоу «Настройка
  restricted-путей»).
- New-режим (6.4.0): источник — нативные permissions OpenCode
  (`.opencode/opencode.json` или global); строка §12
  (`- **Confidential-данные:** p1, p2`) — документация-зеркало;
  плагинная директива `restricted-data paths: …` — производная (из
  нативного конфига при init).
- Проект в legacy-режиме (секция `confidential` есть в `maestro.json`) —
  сначала миграция (см. «Миграция legacy → new» ниже).

## 📖 Пошаговая инструкция — добавить/расширить restricted-путь

1. Запросите `/maestro-assistant «добавить путь <path> к restricted»`.
2. Ассистент прочитает нативный конфиг и строку §12, сформирует diff-merge
   (идемпотентно, с сохранением пользовательских правок) — **одной
   операцией**:
   - нативные deny `read`/`edit`/`glob`/`grep` по каждому пути в
     merge-config (`.opencode/opencode.json`);
   - per-agent allow `custodian`/`sanitizer` (`read`/`glob`/`grep`) на те
     же пути (agent rules take precedence);
   - строка §12 в `docs/project-context.md` (канон M2: одна строка,
     repo-relative пути, через запятую; пути зеркалируют нативные
     deny-паттерны `read`).
3. Покажет адресный diff «стало vs было» и HITL-гейт: (a) approve —
   (b) правки — (c) отмена.
4. При approve — запишет **обе части**. **OP-1:** перезапустите opencode
   (плагин перечитывает нативный конфиг при init и сверяет §12 warn'ом
   `confidential:drift`).
5. **Сверка нативных deny ↔ строка §12** (детектор дрейфа): расхождение
   недопустимо — перегенерация одной операцией.

## 📖 Снятие с защиты (удаление/ослабление пути) — жёсткий блок по умолчанию

- Не инициировать/не выполнять снятие сам — только по явному запросу HITL.
- (а) адресный diff «путь X исключается из нативных deny: данные станут
  доступны primary/untrusted» (+ удаление пути из строки §12);
- (б) явное **отдельное** HITL-подтверждение (OP-4).
- **Merge — только консервативное дополнение:** при повторном прогоне
  только добавлять пути, не удалять/изменять существующие без явного
  HITL-гейта.
- **Адресный показ:** при любом изменении — отдельный diff (стало vs было).

## 📖 Миграция legacy → new (фиксированный порядок)

Проект в legacy-режиме (секция `confidential` есть в `maestro.json`, warn
`confidential:legacy_active`) мигрируется **только в этом порядке**
(нарушение порядка = окно без файловой защиты; warn `confidential:drift` —
детектор нарушенного порядка):

1. **Шаг 0 — предпроверка trust (ДО обновления плагина).** Если в
   `maestro.json` есть `trust.<custom>` (кастомные агенты) — уведомление:
   (6.4.0: секция `trust` не читается **в любом режиме**) — кастомные
   агенты **немедленно** теряют плагинный файловый доступ (fail-closed —
   утечки нет). При необходимости — сначала добавить нативный per-agent
   allow (отдельное HITL-решение).
2. **(1) Одна операция** (HITL-гейт с diff): нативные deny `read`/
   `edit`/`glob`/`grep` + per-agent allow `custodian`/`sanitizer` на
   **все** пути из legacy `confidential.paths` + строка §12 (M2).
3. **(2) Restart + live-проверка нативного deny:** primary — нативный
   permission error при чтении restricted-пути; `custodian`/`sanitizer` —
   чтение работает (per-agent allow).
4. **(3) Только затем** — удалить секцию `confidential` из `maestro.json`
   (адресный diff + **отдельное** HITL-подтверждение). **Предпроверка
   удаления:** нативные deny на все пути §12 (иначе — окно без файловой
   защиты).
5. **(4) Restart + проверка new-режима:** в system-контексте top-level
   primary-сессии — директива `restricted-data paths: …`; warn'ов
   `confidential:legacy_active` нет; плагин не бросает
   `[confidential:deny]` (deny приходят нативно).

## 💡 Примеры масок (нативная семантика)

- Нативный `*` **пересекает `/`** (в отличие от сегментного матчинга
  legacy-плагина): `docs/confidential/*` закрывает директорию,
  поддиректории и вложенные файлы.
- **Last-match-wins:** порядок правил критичен — catch-all (`"*"`)
  первым, специфичные правила после (иначе catch-all перекроет deny).
- Built-in-паттерны секретов (`.env`, `*.pem`, `*.key`, `*.crt`,
  `*.p12`, `*.pfx`) уже в deny-baseline init — не дублировать.

## ⚠️ Чего делать НЕ надо

- НЕ добавлять `docs/superpowers/specs/**` и `docs/superpowers/plans/**`
  в restricted-пути — они двухролевые (уничтожат доступ
  untrusted-субагентов к spec/plan, процесс остановится).
- НЕ снимать пути без явного HITL-запроса и отдельного approve (жёсткий
  блок).
- НЕ менять существующие пути без HITL-гейта (merge — только
  дополнение).
- НЕ добавлять restricted-пути в `memory.history_globs` /
  `memory.artifact_globs` (канон I4 — backfill-канал не должен попадать
  в allowlist).
