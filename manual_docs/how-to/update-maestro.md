# Обновление maestro

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Как обновить скилл `maestro` (скиллы/команды/агенты) и плагин `maestro-bootstrap`
до новой версии authoring-репо, и как проконтролировать, что обновление прошло
до нужной версии.

## 🧩 Механизм доставки

Скиллы/команды/агенты и плагин доставляются единым механизмом: `git clone`
(https-only, shallow) + **wholesale copy** + manifest (через `maestro-update.sh`).
Версия у обеих частей — **единая**, из корневого `package.json` авторского
репозитория `maestro-agent`.

| Часть | Механизм доставки | Контроль версии |
|---|---|---|
| Скиллы/команды/агенты | wholesale copy (через `maestro-update.sh`) | нет отдельной версии; версия = версия дистрибутива из `package.json` |
| Плагин `maestro-bootstrap` | git (`@git+...`), опционально `#<commit-sha>` | `.maestro/plugin-version` + `/maestro-version` |

## 🔍 Единая версия и как её узнать

Версия плагина и скиллов — **одна**: корневой `package.json → version`
авторского репозитория (например, `6.0.0`). Скиллы отдельной версии не имеют;
их версия — это версия дистрибутива `maestro`.

Рантайм-контроль версии — команда `/maestro-version`: она читает
`.maestro/plugin-version` — в проектном режиме файл пишет плагин при каждом
запуске сессии, в глобальном — скрипты установки/обновления (fallback —
глобальный `~/.config/opencode/.maestro/plugin-version`). Если файла нет —
команда сообщает «не инициализирован» (признак сбоя init плагина).

## 📖 Пошаговая инструкция

### Глобальное обновление (рекомендуется)

Одна команда обновляет скиллы/команды/агенты и плагин на всю машину:

```bash
bash maestro-update.sh --global   # опции: --pin <sha>, --prune, --dry-run, --help
```

Последовательность (гарантии надёжности):

1. Preflight + **permission check**: read-only целевой каталог → abort с
   подсказкой про `XDG_CONFIG_HOME`.
2. **Clone-first:** clone maestro + superpowers до любых destructive-действий
   (fail-fast).
3. **Self-check (V21):** скрипт сравнивает своё содержимое со скриптом целевого
   коммита (из полученного clone) — при расхождении warning + HITL-инструкция
   обновления (curl raw-URL); **не блокирует** (см. «Самопроверка версии
   скрипта»).
4. **No-op:** если sha в manifest == sha clone — «актуальная версия (sha …)»,
   exit 0, без изменений.
5. **`--prune` HITL:** JSON-листинг stale-компонентов
   (`[{"path": "skills/x", "reason": "removed_from_repo"}]`) → y/N;
   без `--prune` stale не трогаются (info-hint); non-interactive — fail-closed.
6. **Wholesale copy** (атомарный per-item swap; чужие объекты без маркера
   `.maestro-deployed` не трогаются).
7. **Manifest** (атомарная запись).
8. **Очистка кэша плагина** `~/.cache/opencode/npm/git-maestro-*` + legacy
   `packages/`.
9. **Re-регистрация плагина** в глобальном `opencode.json` (idempotent, de-dup).
10. **HITL-рестарт службы** opencode с предупреждением
    «прервёт все проекты» (рестарт службы прерывает сессии во всех проектах).

После скрипта — перезапустите OpenCode и выполните `/maestro-version`
для контроля.

### Проектное обновление

```bash
bash maestro-update.sh                  # --project — default
bash maestro-update.sh --project --dry-run   # план без изменений (0 мутаций)
```

Последовательность: clone-first → self-check → no-op-проверка → `--prune` HITL
→ wholesale copy в `.opencode/` → manifest → очистка кэша плагина →
re-регистрация плагина в `.opencode/opencode.json` → «перезапустите opencode».

После скрипта — перезапустите OpenCode и выполните `/maestro-version`.

### Самопроверка версии скрипта

`maestro-update.sh` при запуске (до любых изменений) сравнивает собственное
содержимое со скриптом целевой версии (из уже полученного clone — без доп.
сетевых вызовов). Сравнивается **содержимое**, не семантическая версия: при
`--pin` — со скриптом закреплённого коммита.

При расхождении:

```
[maestro-update] ВНИМАНИЕ: self-check: запущенный maestro-update.sh устарел —
отличается от версии в коммите <sha>.
  HITL-самообновление (обновление НЕ автоматическое). Обновите скрипт и
  перезапустите:
    curl -fsSL https://raw.githubusercontent.com/wad-jet/maestro/<sha>/maestro-update.sh -o maestro-update.sh
```

- Самообновление **не автоматическое** (silent self-update запрещён) — скрипт
  продолжает работу текущей версией; обновить нужно вручную (команда выше).
- Неинтерактивный режим: warning, продолжение (не блокирует, в т.ч. `--dry-run`).

Если `maestro-update.sh` ещё нет — возьмите из репозитория:

```bash
curl -fsSL https://raw.githubusercontent.com/wad-jet/maestro/main/maestro-update.sh -o maestro-update.sh
```

### Пиннинг версии (`--pin <sha>`)

`--pin <sha>` фиксирует maestro и superpowers на указанном коммите; плагин
регистрируется как `spec#sha`. Атомарность: один sha = одна версия скиллов и
плагина (защита от версионного дрейфа). Для superpowers, если коммита там нет
(он не содержит коммитов maestro) — main + warning. Без `--pin` — голова ветки.

### Кэш плагина (ручное обновление)

Плагин ставится из git-репозитория
`maestro-bootstrap@git+https://github.com/wad-jet/maestro.git` и **кэшируется**
в `~/.cache/opencode/npm/git-maestro-*/` (V2-layout; ранее —
`~/.cache/opencode/packages/`) при установке. **Кэш не обновляется при
перезапуске OpenCode** — перезапуск сам по себе НЕ подтягивает новую версию из
ветки репозитория. Чтобы обновить плагин, нужно очистить кэш:

```bash
rm -rf ~/.cache/opencode/npm/git-maestro-*
```

Затем перезапустите OpenCode — плагин переустановится из git заново.
`maestro-update.sh` очищает кэш автоматически (в обоих режимах).

> **Не смешивайте ключи `plugin` (V1) и `plugins` (V2)** — двойная регистрация
> даёт «Duplicate plugin ID» и toast при старте. `maestro-update.sh` /
> `maestro-install.sh` мигрируют legacy-ключ автоматически.
>
> **Не копируйте папку плагина отдельно от репозитория** — версия не определится
> (`/maestro-version` сообщит «не инициализирован»).
>
> **`maestro-install.sh` — только первичная установка.** Для обновления
> используйте `maestro-update.sh`, а не `maestro-install.sh` (тот рассчитан на
> первый bootstrap).

### Контроль обновления

Порядок обязателен: **обновить (скиллы + плагин — с очисткой кэша) →
перезапустить → проверить**.

1. **Перезапустите OpenCode.** До перезапуска `.maestro/plugin-version`
   содержит старую версию (файл перезаписывается при init).
2. Выполните `/maestro-version` — покажет фактическую версию из
   `.maestro/plugin-version` (глобальный режим: fallback на глобальный
   `~/.config/opencode/.maestro/plugin-version`).
3. Сверьте с версией из кэша плагина (`node_modules/maestro-bootstrap/package.json`)
   (это версия и скилов, и плагина). Расхождение → скилы/плагин не той версии.
4. Если команда сообщает «не инициализирован или версия неизвестна» — плагин
   не загрузился / сбой init.

### Проверка после перезапуска (smoke-чеклист)

После обновления и перезапуска OpenCode проверьте:

1. Версия в init-логе = версия из кэша плагина.
2. Memory-инструмент доступен: `@maestro-memory` показывает статус (не
   «плагин недоступен»).
3. `@maestro-memory-report` собирает отчёт.

**Rollout-порядок для релизящего (при публикации новой версии maestro):**
1. **Push** новой версии в remote-репозиторий (wad-jet/maestro).
2. **Обновление** — `maestro-update.sh --global` (скиллы/команды/агенты +
   плагин: wholesale copy, очистка кэша, HITL-рестарт службы) либо
   `maestro-update.sh` по проектам (проектный режим).
3. Проверить: `/maestro-version` = новая версия; smoke-чеклист выше.

Порядок нарушать нельзя: **push ДО очистки кэша/перезапуска** — иначе кэш
подтянет старую версию и перезапуск будет потерян (инцидент 09-09).

## ⚠️ Известные ограничения

- Плагин кэшируется в `~/.cache/opencode/npm/git-maestro-*` (V2-layout) и НЕ
  обновляется при перезапуске OpenCode — кэш нужно очищать
  (`maestro-update.sh` делает это сам).
- У скилов нет отдельной версии — их версия = версия дистрибутива из
  `package.json`. Гарантия версии сборки — `--pin <sha>` (плагин
  регистрируется как `spec#sha` — один коммит на скиллы и плагин).
- Плагин резолвит версию только при целостной установке из репозитория (из
  корневого `package.json`).
- Доставка — wholesale copy: новый компонент авто-deploy при следующем
  обновлении; stale-компоненты (переименования/удаления) удаляются только с
  `--prune` (HITL-листинг).
- Глобальное обновление требует HITL-рестарта службы («прервёт все проекты»);
  проектное — перезапуск текущего проекта.
