# Обновление maestro

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Как обновить скилл `maestro` (скиллы/команды/агенты) и плагин `maestro-bootstrap`
в целевом проекте до новой версии authoring-репо, и как проконтролировать, что
обновление прошло до нужной версии.

Обновление состоит из **двух независимых частей** с разными механизмами доставки.
Версия у обеих частей — **единая**, из корневого `package.json` авторского
репозитория `maestro-agent`.

## 🧩 Две части и их контроль версии

| Часть | Механизм доставки | Контроль версии |
|---|---|---|
| Скиллы/команды/агенты | `agpack sync` / вручную из репозитория | нет отдельной версии; версия = версия дистрибутива из `package.json` |
| Плагин `maestro-bootstrap` | git (`@git+...`), опционально `#<commit-sha>` | `.maestro/plugin-version` + `/maestro-version` |

> `agpack` не покрывает плагин и конфиги (`maestro.json`, `.gitignore`,
> `regression/`; модели — `.opencode/opencode.json` или global) — их создаёт
> `/maestro-init`. Скиллы/команды/агенты (`агpack`) и плагин/конфиги доставляются
> разными механизмами.

## 🔍 Единая версия и как её узнать

Версия плагина и скилов — **одна**: корневой `package.json → version` авторского
репозитория (например, `1.2.2`). Скиллы отдельной версии не имеют; их версия —
это версия дистрибутива `maestro`.

Рантайм-контроль версии — команда `/maestro-version`: она читает файл
`.maestro/plugin-version`, который плагин при каждом запуске сессии пишет из
`package.json`. Если файла нет — команда сообщает «не инициализирован» (признак
сбоя init плагина).

## 📖 Пошаговая инструкция

### Шаг 1: Обновление скиллов/команд/агентов

**Вариант 0 — через `maestro-update.sh` (рекомендуется):**

Одна команда делает всё: определяет целевую версию, запускает `agpack sync`,
очищает кэш плагина (см. Шаг 2), пишет `expected_version` в `maestro.json`.
Опционально — закрепить конкретный коммит через `--pin <sha>`.

```bash
bash maestro-update.sh          # опции: --pin <sha>, --global, --help
```

> Скрипт `maestro-update.sh` уже загружен в проект при первичной установке
> (`maestro-init.sh` скачивает его автоматически). Если его нет — возьмите из
> репозитория:
> ```bash
> curl -fsSL https://raw.githubusercontent.com/wad-jet/maestro/main/maestro-update.sh -o maestro-update.sh
> ```

После скрипта — перезапустите OpenCode и выполните `/maestro-version` для контроля.

**Вариант A — через `agpack`:**

```bash
agpack sync        # разворачивает актуальные skills/commands/agents в .opencode/
```

`agpack sync` обновляет зависимости из `agpack.yml` до последней версии ветки
указанных репозиториев.

**Вариант B — вручную:** скопируйте `skills/`, `commands/`, `agents/` (и при
необходимости `.opencode/`) из авторского репозитория в целевой проект.

### Шаг 2: Обновление плагина

Плагин ставится из git-репозитория
`maestro-bootstrap@git+https://github.com/wad-jet/maestro.git` и **кэшируется** в
`~/.cache/opencode/packages/` при установке. **Кэш не обновляется при перезапуске
OpenCode** — перезапуск сам по себе НЕ подтягивает новую версию из ветки
репозитория. Чтобы обновить плагин, нужно очистить кэш.

**Рекомендуемый способ — `maestro-update.sh`:** скрипт очищает кэш плагина
автоматически (см. Шаг 1, Вариант 0).

**Ручной способ:** очистите кэш плагина вручную и перезапустите OpenCode:

```bash
rm -rf ~/.cache/opencode/packages/maestro-bootstrap@git+https:...
```

Затем перезапустите OpenCode — плагин переустановится из git заново.

Чтобы зафиксировать конкретную версию/коммит — укажите fragment (то же через
`maestro-update.sh --pin <sha>`):

```jsonc
// .opencode/opencode.json или opencode.json
{
  "plugin": [
    "maestro-bootstrap@git+https://github.com/wad-jet/maestro.git#<commit-sha>"
  ]
}
```

> **Не копируйте папку плагина отдельно от репозитория** — версия не определится
> (`/maestro-version` сообщит «не инициализирован»).
>
> **`maestro-init.sh` — только первичная установка.** Для обновления используйте
> `maestro-update.sh`, а не `maestro-init.sh` (тот рассчитан на первый bootstrap
> нового проекта).
>
> **Merge-add-семантика `agpack`:** `maestro-update.sh` добавляет отсутствующие
> записи в `agpack.yml`, но **не удаляет** устаревшие. Конвенция: каждый новый
> компонент (skill/command/agent) релиза добавляется в `maestro-init/agpack.yml`.

### Шаг 3: Контроль обновления

Порядок обязателен: **обновить → перезапустить → проверить**.

1. **Перезапустите OpenCode.** До перезапуска `.maestro/plugin-version` содержит
   старую версию (файл перезаписывается при init).
2. Выполните `/maestro-version` — покажет версию из `.maestro/plugin-version` и
   сравнит её с ожидаемой из `.maestro/expected-version`. При рассинхроне — команда
   предупредит об этом.
3. Сверьте с ожидаемой версией из `package.json` (это версия и скилов, и плагина).
   Расхождение → скилы/плагин не той версии.
4. Если команда сообщает «не инициализирован или версия неизвестна» — плагин не
   загрузился / сбой init.

## ⚠️ Известные ограничения

- Плагин кэшируется в `~/.cache/opencode/packages/` и НЕ обновляется при
  перезапуске OpenCode — кэш нужно очищать (`maestro-update.sh` делает это сам).
- У скилов нет отдельной версии — их версия = версия дистрибутива из `package.json`.
- `agpack` не пинит скилы по версии (только ветка). Гарантия версии сборки — пинить
  плагин на тот же коммит `#<commit-sha>`, что и источник скилов.
- Плагин резолвит версию только при целостной установке из репозитория (из корневого
  `package.json`).
