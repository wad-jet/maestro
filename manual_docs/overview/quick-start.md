# Быстрый старт

[Назад к оглавлению](../index.md)

## 🎯 Назначение

Минимальный путь к запуску фичи через скилл `maestro`. Для первого полного
прохода с объяснениями — см. [Запуск первой фичи](../tutorials/run-first-feature.md).

## 📋 Предпосылки

- Целевое приложение содержит `.opencode/` с агентами, скиллами и командами maestro
  (доставляются из авторского репо вручную или через `agpack`).
- Проект настроен: `docs/project-context.md` (секция 14 — Commands), конфигурация
  maestro. Если ещё не настроен — выполните
  [Настройку проекта для maestro](../tutorials/setup-project.md) (`/maestro-init`).
- Модели агентов настроены в `opencode.json`.

## 🚀 Пошагово

### Шаг 1: Вызовите скилл

В сессии OpenCode вызовите `/maestro` с описанием задачи.

### Шаг 2: Пройдите начальные гейты

1. Загрузка Project Context (шаг 0) — подтвердите актуальность.
2. Выбор маршрута (шаг 1) — `(f) feature`.
3. Выбор режима (шаг 1.5) — `(a) efficient` или `(b) interactive`.
4. Pre-flight диагностика (шаг 2) — `(a) да`.
5. Выбор изоляции (шаги 3–6) — worktree или ветка.

### Шаг 3: Определите категорию фичи (шаг 7)

- `(b) Простая` — шаги spec пропускаются, сразу к плану.
- `(a) Сложная/Архитектурная` — полный pipeline со spec и Spec Review.

### Шаг 4: План и реализация

- Шаг 11 — план задач.
- Шаг 12 — утвердите план `(a) Approve`.
- Шаг 13 — реализация субагентами с per-task ревью.

### Шаг 5: Проверки и завершение

- Шаги 14–16 — документация, тесты, build, финальное ревью.
- Шаг 17 — `(a) Approve merge`.
- Шаг 18 — merge в base-ветку.

## 💡 Совет

Для простой фичи (1–2 файла) достаточно маршрута
`0 → 6 → 7(b) → 11 → 13 → 16 → 18` — тяжёлый spec/Spec Review не требуется.

## ⚠️ Известные ограничения

- `continue` / «давай» **не** являются подтверждением последующих гейтов —
  каждый гейт требует отдельного ответа.
- Trivial fix (1–2 строки) — maestro не нужен, используйте `@haiku` напрямую.
