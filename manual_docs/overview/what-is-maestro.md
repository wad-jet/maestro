# Что такое maestro

[Назад к оглавлению](../index.md)

## 🎯 Назначение

`maestro` — агент для OpenCode, который оркестрирует сквозную реализацию фич и
багфиксов в целевом приложении. Он проводит работу от идеи до мержа: дизайн
(brainstorm primary + custodian Q/A по confidential), спецификация, план, реализация (SDD), ревью и документация —
с HITL-гейтами на ключевых точках.

**Core principle:** оркестратор координирует — субагенты реализуют. HITL-гейты
на ключевых точках. Spec Review — только по запросу.

> **Не только код.** `maestro` управляет проектами через контекст и процессы
> (спеки, планы, ревью, реестр регрессии), поэтому применим не только к
> код-проектам, но и к задачам с промптами скиллов, регрессионным сценариям и
> иным контентным изменениям.

## 📦 Как maestro встраивается

- **Источник истины** — конфигурация живёт в authoring-репо `maestro-agent`
  (`skills/`, `agents/`, `commands/`, `plugins/`).
- **Runtime** — OpenCode загружает скиллы/агентов/команды из целевого приложения в `.opencode/`
  (`agents/`, `skills/`, `commands/`). Доставка в целевое приложение — **штатным механизмом**
  (вручную из удалённого репозитория или через `agpack`); отдельное зеркалирование не требуется.
- **Точка входа** — команда `/maestro-init` в любой primary-сессии загружает скилл и
  следует pipeline. Отдельного primary-агента `maestro` нет — только скилл и
  команда.
- **Консультации по конфигурации** — `/maestro-assistant`: общий источник правил
  конфигурации/структуры/контекста и лёгкая точка входа для настройки проекта
  в течение его жизни.
- **Плагин** `maestro-bootstrap` — глобальная observability (логирование
  `task`-диспатчей и ошибок сессий), не привязан к агенту.

## 🔀 Маршруты

| Маршрут | Описание |
|---|---|
| **Feature** (шаги 0–18) | Полный цикл: project context → pre-flight → дизайн (brainstorm primary + custodian Q/A) → spec → plan → SDD → docs → review → finish |
| **Bugfix** (шаги 0–6 → D1–D7 → шаги 11–18) | Ресеч → гипотеза → probe → откат → plan → SDD → docs → review → finish |
| **Spike** (feasibility) | Короткий ресеч/прототип → рекомендация; без spec/plan/мержа; throwaway-код |

## 🧭 Ключевые понятия

- **HITL-гейты** — точки, где агент останавливается и ждёт явного ответа
  пользователя (варианты a/b/c). Подробнее — [Справочник HITL-гейтов](../reference/hitl-gates.md).
- **Категория фичи** — определяет глубину pipeline (простая / сложная /
  архитектурная). Подробнее — [Классификация фич](../reference/feature-classification.md).
- **Режимы работы** — `efficient` (молча между гейтами) и `interactive`
  (комментирует находки по ходу).
- **Реестр регрессии** — фиксация рисков изменения кодовой базы.
  Подробнее — [Работа с реестром регрессии](../how-to/use-regression-registry.md).
