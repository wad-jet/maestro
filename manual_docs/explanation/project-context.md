# Project Context

[Назад к оглавлению](../index.md)

## 🎯 Назначение

`docs/project-context.md` — постоянный контекст проекта, который maestro загружает на шаге 0 каждого pipeline. Оркестратор читает его для понимания стека, архитектуры, команд тестирования, процессов — без необходимости повторно спрашивать.

## 📖 Структура: 14 категорий

Файл состоит из 14 секций (категорий). Минимальный набор обязательных: **1, 2, 3, 4, 9, 14**. Остальные заполняются по релевантности или помечаются `_pending_`.

### Обязательные секции

| № | Название | Что содержит | Пример |
|---|---|---|---|
| 1 | **Название и назначение** | Описание проекта, аудитория, тип (сервис, app, библиотека, CLI, monorepo) | `REST API на NestJS…` |
| 2 | **Цели и метрики успеха** | Бизнес-цели, North Star, KPI, non-goals | `Reduce latency < 200ms…` |
| 3 | **Стек технологий** | Языки, фреймворки, ORM, БД, кэш, очереди, инструменты | `NestJS, PostgreSQL, Redis, Prisma` |
| 4 | **Архитектура** | Слои, границы модулей, потоки данных | `endpoint → сервис → репозиторий` |
| 9 | **Критерии приёмки** | Definition of Done, покрытие тестами, gate перед merge | `80% coverage, lint clean` |
| 14 | **Commands** | Тесты, билд, линт, e2e, coverage — для каждого сервиса/подкаталога | `TEST_COMMAND: "npm run test:unit"` |

### Опциональные секции

| № | Название | Зачем |
|---|---|---|

## 📝 Секция 14: Commands

Критически важна — определяет команды, которые maestro выполняет на шагах 15/15a pipeline.

### Формат

```yaml
## 14. Commands

### Default (root)
TEST_COMMAND: "npm run test:unit"
BUILD_COMMAND: "npm run build"
E2E_COMMAND: "npm run test:e2e"              # опционально
LINT_COMMAND: "npm run lint"
DOCS_COVERAGE_COMMAND: "npm run docs-coverage"  # опционально
OBSERVABILITY_COVERAGE_COMMAND: "npm run obs-coverage"  # опционально

### services/etl-go/
TEST_COMMAND: "go test ./..."
BUILD_COMMAND: "go build ./..."
```

### Поля

| Поле | Назначение |
|---|---|
| `TEST_COMMAND` | Unit-тесты (выполняются на шагах 15/15a) |
| `BUILD_COMMAND` | Сборка проекта (шаг 15a) |
| `E2E_COMMAND` | End-to-end тесты (шаг 15) |
| `LINT_COMMAND` | Линтинг (шаг 15) |
| `DOCS_COVERAGE_COMMAND` | Покрытие документации (шаг 15). Если не задана/`none` — на шаге 14 используется diff-сверка как fallback |
| `OBSERVABILITY_COVERAGE_COMMAND` | Покрытие observability (шаг 15) |

### Значения

Каждая команда поддерживает три режима. При опросе `/maestro-init` эти значения
предлагаются через вопросный инструмент как выбираемые варианты (radio) + «свой
вариант» (ввод команды вручную):

| Значение | Поведение |
|---|---|
| `"npm run test:unit"` | Явная команда — выполняется как есть |
| `"auto"` | Авто-детект по `skills/maestro/stack-detection.md` — результат HITL persist |
| `"none"` | Пропустить шаг в pipeline |

### Подсекции

Каждая подсекция `### <путь>/` определяет команды для конкретного каталога сервиса. Если не задана для сервиса — используются команды из `### Default (root)`.

## 🔧 Как создаётся

`/maestro-init` проходит все 14 категорий интерактивно, задаёт вопрос, фиксирует ответ, собирает файл. Существующий файл не перезаписывается — обновляется через HITL-диалог.

**Актуализация/наполнение в течение жизни проекта** — через `/maestro-assistant` (правила
актуализации в скилле `maestro-assistant`). Схема 14 категорий остаётся каноном в
`init-context.md`; `/maestro-assistant` правит только наполнение секций.
