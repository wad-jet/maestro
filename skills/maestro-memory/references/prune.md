# Prune памяти (глава)

> Канон: prune. Грузится командой `@maestro-memory-prune` (тонкий лоадер).
> Ядро скилла `maestro-memory` в контексте: Гейт доступности (п. 1.1–1.4)
> пройден, состояние памяти известно.

Покажи кандидатов на удаление в **memory layer** и удали их с HITL-подтверждением.

## Если память off / плагин недоступен

Если Гейт доступности (ядро скилла `maestro-memory`) определил состояние
«disabled» (reason-код) или «плагин недоступен» — выведи причину по
reason-коду из Гейта доступности (ядро) + рекомендацию по исправлению
(включая `memory_probe`-диагностику при `embedder_probe_hard_fail`) и
заверши.

## Шаг 1. Доступность

1. Вызови инструмент `memory_prune` с `action: "list"`.
2. Если инструмент недоступен / память выключена → покажи причину по Гейту доступности (ядро скилла `maestro-memory`).

## Шаг 2. Листинг

Покажи категории:
- `remote-merged` / `remote-alive` — влито/запушено, НЕ кандидаты;
- `local-only` — живая, только локально (host);
- `dead` — брошенная, кандидат;
- `unknown` (head='') — кандидат 1-го класса.

Обнови свежесть: предложи выполнить `git fetch --prune` (с согласия пользователя),
затем повторный `list` — листинг честен по состоянию refs на текущем хосте.
Покажи squash/rebase-предупреждение из вывода инструмента.

## Шаг 3. HITL-подтверждение

Спроси, что удалить:
- выборочно по `session_ids`/`heads`;
- категорией (`dead` | `unknown`).

На централизованных бэкендах (qdrant/pgvector) foreign-host записи исключены из
batch-all (выбор по явным session_ids/heads). Никогда не удаляй без явного
подтверждения пользователя (permission: ask).

## Шаг 4. Удаление

Вызови `memory_prune` с `action: "delete"` и явным набором. Покажи результат и
предложи перезапустить `list`, чтобы увидеть остаток.
